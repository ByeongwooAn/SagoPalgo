# U06 소켓 장애 주입과 자동 복구

기준일: 2026-11-06. **실제 루프백 TCP/WebSocket과 격리 MySQL을 사용한 개발·회귀 범위를 완료했습니다.** KIS 형식의 프레임과 승인 응답은 합성 자료입니다. 이 결과는 KIS 서버의 장중 장애 복구·구독 한도·실시세 재수신 검증이 아닙니다. **KIS 장중 제한 실증(U06-B)은 근거 대기**로 남깁니다. 현재 작업은 운영 서버·수집 설정·기존 DB·계좌/주문을 변경하지 않습니다.

## 원인과 수정

기존 구현은 ACK 수신만으로 실패 횟수를 초기화했습니다. 따라서 연결·ACK·즉시 단절을 반복하면 연속 실패 상한을 피할 수 있었습니다. 승인 요청·연결 대기·구독 송신 대기/간격도 제어 스케줄러와 섞여 있어, 그 대기 중 watchdog의 실행이 지연될 수 있었습니다. 연결 세대 확인 이후 저장/공개 시점 사이에 세대가 바뀌는 경계도 별도 보호가 필요했습니다.

- **제어와 대기 분리:** 승인 HTTP는 별도 연결 실행기에서 수행합니다. WebSocket 접속·구독 송신은 완료 future와 제한 시간으로 처리하며 제어 스케줄러에서 `get`/`sleep`으로 기다리지 않습니다. 연결/구독 대기 중에도 watchdog과 종료가 진행됩니다.
- **실패 상한:** ACK만으로 실패 횟수를 초기화하지 않습니다. 같은 연결에서 ACK 완료 후 60초 이상 유지되고, 각 종목의 체결/호가에 새로 저장된 최신 자료가 있어야 초기화합니다. 중복 재생이나 오래된 체결만으로 안정 복구를 인정하지 않습니다. 연속 실패 8회 또는 거절/잘못된 프레임 등의 치명적 실패는 종결합니다.
- **재시도 소유권:** 연결 세대 증가·pending 연결/송신/승인/재시도 취소·재시도 예약을 같은 수명 관리 구간에서 처리합니다. 이전 세대의 오류·ACK·송신 완료가 새 연결을 변경하지 못하며, 중지 후 예약 재접속도 실행하지 않습니다.
- **공개 세대:** 소켓이 열린 때의 Hub 세대를 저장 처리까지 전달합니다. 이전 세대 입력은 공개되지 않고 늦은 afterCommit도 새 연결에 투영되지 않습니다. 이전 세대의 공개 기록 실패 역시 새 Hub를 FAILED로 바꾸지 않습니다. 이미 커밋된 원본을 삭제하거나 성공으로 바꾸지는 않습니다.
- **조회와 중지:** 분봉 DB 조회를 Hub의 공개/연결 모니터 밖으로 옮겼습니다. 느린 분봉 조회가 소켓 종료를 막지 않으며, 조회가 늦게 끝나도 이전 LIVE 상태를 반환하지 않습니다. 중지는 로컬 상태를 `DISABLED/COLLECTOR_STOPPED`로 전환하고 최신 체결/호가 투영을 비웁니다. `enabled`는 설정값으로 보존합니다.
- **PING/PONG:** 프로토콜 Ping의 자동 Pong은 [Java 17 WebSocket 계약](https://docs.oracle.com/en/java/javase/17/docs/api/java.net.http/java/net/http/WebSocket.html)을 따릅니다. KIS JSON PINGPONG에는 별도 Pong을 보냅니다. Ping이 계속 와도 ACK 제한 시간은 독립적으로 만료되며, 바이너리 프레임은 공개 시세 입력으로 수용하지 않습니다.

일반 운영의 KIS endpoint·구독 대상·1종목당 2개 TR·승인키 메모리 캐시는 유지했습니다. 루프백 endpoint·짧은 시험 시간·고정 UTC는 package-private 테스트 생성자로만 주입하며 운영 설정이나 외부 API로 열지 않습니다.

## 운영 시간값과 상태 의미

| 항목 | 운영 값 / 처리 |
|---|---|
| 연결 시도 | 최대 15초 |
| 송신 완료 대기 | 최대 10초 |
| 구독 송신 간격 | 1초 |
| ACK 미확정 | 60초 이후 재연결 |
| 소켓 활동 없음 | 60초 이후 재연결 |
| watchdog 점검 | 10초 간격, 임계값과 실제 감지 시각은 구분 |
| 재시도 지연 | 5·10·20·40·60초, 이후 상한 60초 |
| 안정 복구 초기화 | ACK 후 60초 유지 + 모든 구독의 새 최신 저장 자료 |
| 실패 종결 | 연속 8회 또는 치명적 오류 |

데이터가 없지만 Ping은 정상인 조용한 종목/구간을 네트워크 장애로 단정하지 않습니다. 이런 경우 Hub는 자료의 최신성에 따라 WAITING_DATA/STALE을 표시하며 LIVE로 승격하지 않습니다. 피드별 지연·장중 부하·장기 관찰은 U07/D03의 운영 근거와 연결합니다.

연결 객체는 상태·고정 진단 코드·세대·로컬 단조 경과 시각을 최대 128개 메모리 영수증으로 보관합니다. 자격값·프레임·가격·계좌정보는 포함하지 않습니다. 시계 도메인은 프로세스/객체 단위이며 `utcSynchronized=false`입니다. 이 영수증은 DB의 영구 운영 원장이나 과거 누락 틱 복구 기능이 아닙니다. 테스트가 해당 시점의 영수증을 Git 제외 폴더에 배타적으로 저장합니다.

## 검증한 범위

로컬 RFC6455 서버가 실제 Java HttpClient/WebSocket과 연결합니다. 승인 HTTP만 모의 응답이고 프레임은 합성입니다. 콜백을 직접 부르는 검사와 실제 전송 계층 검사를 구분합니다.

| 상황 | 확인한 결과 |
|---|---|
| TCP RST·정상 Close | 프로세스 재시작 없이 새 연결·체결/호가 재구독, 새 자료 전에는 이전 시세 없음 |
| 분할 프레임·중복 재생·누적량 공백 | 프레임 재조립, 동일 체결 중복 가산 없음, 미관측 체결 생성 없음 |
| ACK 누락 + 지속 Ping | Pong 응답을 유지하면서 별도 SUBSCRIBE_TIMEOUT으로 복구 |
| ACK 후 무응답 | HEARTBEAT_TIMEOUT으로 자동 재접속 |
| ACK 후 빠른 단절 반복 | 8회에서 FAILED, 추가 소켓 없음 |
| 새 최신 체결/호가 + 안정 시간 | 이후에만 실패 예산 초기화 |
| 최근 수신 이후 시각상 STALE | 패킷 수신 경과만으로 안정 복구를 인정하지 않고 실패 예산 유지 |
| 구독 거절·바이너리 | 치명적 종결·추가 연결 없음, 외부 오류/승인키 비노출 |
| 재시도 대기·핸드셰이크·분봉 조회 중 중지 | 로컬 시험에서 중지 호출 1초 이내, 늦은 완료 후 재접속/LIVE 복원 없음 |
| 늦은 커밋·이전 공개 실패 | 새 연결에 이전 자료나 실패 상태가 섞이지 않음 |
| 실제 격리 MySQL 저장 | 재연결/재생 후 체결 2행·분봉 관측량 2 유지. 누적량 1→4의 차이를 임의 체결로 채우지 않음 |

신규 15개 검사는 실제 루프백 TCP 검사 14개(격리 MySQL 연결 1개 포함)와 공개 세대 실패 단위 검사 1개입니다. 관련 기존 스트림 검사까지 31개입니다. 전체 백엔드 회귀에는 전용 계좌/주문/시장 DB의 검사도 포함합니다. 최종 건수·Java→Python 감사 결과는 [공개 검증 요약](examples/socket-recovery-validation.json)에 기록합니다.

최종 **전체 백엔드 796건 통과·실패/오류/제외 0건**입니다. 저장/내보내기 4행을 Python 틱 감사로 다시 읽어 체결 2·호가 2, 누적량 공백 1건을 검출했고 빠진 체결은 0건 생성했습니다. 새 입력의 ISO 시각·원문 해시도 검증했습니다. AI Python 런타임 소스는 변경하지 않았으므로 직전 전체 AI 검사 수를 이번 전체 재실행으로 보고하지 않습니다. Java 기존 deprecated API 및 JVM CDS 안내는 검증 실패와 구분합니다.

원문 역할의 합성 프레임은 테스트 소스에 있으며 수신 이벤트·영수증·내보내기·JUnit/로그는 Git 제외 `Back/spring-server/build-codex-socket-recovery/`에 보존합니다. 운영 시세나 실제 계좌 키를 사용하지 않았습니다. 기존 기본 `build/classes`의 Windows 잠금은 수동 삭제·서버 중지 없이 별도 Gradle 출력으로 재실행했습니다. Java 17에서 실행했으며 컴파일/테스트 뒤 패키징·배포·EXE 재빌드는 하지 않았습니다.

## 재실행

`Back/spring-server`에서 관련 검사는 다음과 같이 실행할 수 있습니다. 기존 잠긴 빌드를 우회할 때는 로컬 init 파일에 `allprojects { layout.buildDirectory.set(layout.projectDirectory.dir('build-codex-socket-recovery/gradle')) }`를 지정하고 `-I`로 사용합니다. 운영 endpoint를 로컬 서버로 바꾸는 환경 설정은 없습니다.

```powershell
.\gradlew.bat -I build-codex-socket-recovery/build.init.gradle test --tests '*MarketStreamTest' --tests '*KisStreamSocketRecoveryTest'
# 기존 전용 Compose와 마커 검사를 통과한 경우에만 MySQL 검사를 추가합니다.
$env:SAGOPALGO_MARKET_RESEARCH_MYSQL_TEST='true'
.\gradlew.bat -I build-codex-socket-recovery/build.init.gradle test --tests '*KisStreamSocketMysqlIntegrationTest'
```

운영 DB 대신 기존 `compose.market-research-test.yml`의 33318 마커/tmpfs DB를 사용합니다. 전체 회귀의 계좌·주문 DB도 각각 기존 전용 Compose의 33317/33316을 사용했습니다. 테스트가 소유한 컨테이너만 종료하고 운영 3306 및 Spring/프록시는 유지합니다. 환경 플래그/JAVA_HOME은 각 명령 이후 원래 값으로 복원합니다.

## 다음 작업과 남은 실행 단위

**다음은 U06-B KIS 장중 제한 장애 복구 실증**입니다. 이번 한국 야간 작업의 합성 자료를 장중 공급자 검증으로 바꾸지 않습니다. 해당 실행 단위에서 일회성 probe와 상한을 준비하고 아래 조건으로 실제 자료를 확보합니다.

1. 당시의 공유 키 사용 여부·현재 구독 예산·정규장 표본 구간을 확인하고 운영 수집과 분리한 1종목/2구독 범위를 고정합니다.
2. 새 체결/호가 수신을 확인한 연결 하나만 끊고, 프로세스를 재시작하지 않은 내부 재접속·각 TR ACK·새 자료 수신을 기록합니다. 다른 서비스/전체 네트워크를 끊지 않습니다.
3. 단절 전·후 원문과 해시·세대/단조 시각 영수증·중복/공백을 대조합니다. 공급자 순서/누락 체결을 생성하거나 안정 시간 전에 실패 횟수를 초기화하지 않습니다.
4. 관찰·재시도·종료 상한과 이후 추가 연결 없음을 확인하고, 일회성 수집기를 종료해 기존 OFF 상태를 유지합니다. 진행 중 승인 요청의 공급자 측 취소/구독 해제 완료 여부는 별도 실환경 근거로 확인합니다.

이 조건을 충족해야 U06 전체를 완료로 올립니다. 이후 **U07 세션 전체·장기 운영 관찰**, **U08 과거 CB/단일가 표본**이 별도 단위입니다. U04 실제 비용 계약·U05 독립/계좌 체결은 기존 근거 대기를 유지합니다. 이번 로컬/격리 검증으로 ③-06·5-09 전체를 체크하지 않으며 고정 27/48·56%, 5번 7/18·39%, 5-08 진행 중을 유지합니다.
