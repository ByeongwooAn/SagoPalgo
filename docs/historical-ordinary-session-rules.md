## 공식 포털과 판본 식별

KRX [규정 안내](https://regulation.krx.co.kr/contents/RGL/01/01010000/RGL01010000.jsp)가 연결하는 [새 법무포털](https://rule.krx.co.kr/out/index.do)을 확인했습니다. 기존 `law.krx.co.kr` 접근은 시간이 초과됐습니다. 검색 결과의 과거 날짜 URL을 근거로 사용하지 않고 새 포털의 공개 규정 목록·연혁·본문을 확보했습니다.

본문 조회는 `POST https://rule.krx.co.kr/out/regulation/regulationViewPop.do`이며 `bookid`, `noformyn=N`으로 판본을 선택합니다. 목록에 표시된 날짜는 검토 입력값이고, 실제 본문의 제목·개정 차수·규정 번호·시행일·제4조 본문에 연결된 판본 ID와 다시 대조합니다. 요청 URL 또는 HTTP 200만으로 확보 완료를 판정하지 않습니다.

제4조의 정규시장 행을 검사하고 호가접수·장중경쟁대량매매·시간외시장 시각을 대체 입력으로 쓰지 않습니다. 과거 코스닥의 오전/오후 표기와 새 24시간 표기를 구분합니다. 2026년 시간외시장 변경은 정규장 종료시각 변경으로 해석하지 않습니다. 종가 단일가 결정에 따른 종료 연장과 임시 변경 가능성도 보존하므로, 15:30을 모든 날짜의 최종 체결 시각으로 단정하지 않습니다.

## 코스닥 제53차의 미해결 원문 문제

제53차 bookid `210016900` 요청은 HTTP 200이지만, 반환 본문은 **제52차·제2085호·시행일 2023-01-25**입니다. 정식 제52차 bookid `204845050` 요청의 본문과 바이트 해시도 같습니다. 연혁의 제53차·제2280호 정보와 현재 본문의 해당 부칙 존재만으로 제53차 전문을 확보한 것으로 간주하지 않습니다.

- `EFFECTIVE_DATE_PLACEHOLDER=1`: 목록의 `9999-12-31`을 실제 시행일로 사용하지 않음
- `RULE_VERSION_MISMATCH=1`: 요청한 판본과 다른 본문이 반환됨
- 두 진단은 **같은 미해결 1건**에 해당함
- 원문·요청 필드·요청 시각·반환된 식별값을 함께 보존하고 자동 재시도하지 않음
- 코스닥 전체 규정 연결의 `historicalRuleContinuityConfirmed=false` 유지

다음 작업은 **제2280호의 올바른 전문과 실제 시행일 근거 확보**입니다. 포털의 제4조 연혁 화면도 탐색 자료로 보존했지만, 다른 양식의 대체 판본으로 자동 채택하지 않았습니다. 이후 양 시장의 임시 변경 공지 목록을 기간 전체 대조해야 실제 일반 세션을 확정할 수 있습니다.

## 구현과 재현

`app.replay.historical_session_rules`에 capture/build/audit/as-of를 추가했습니다. 검토 목록은 [historical-session-rules.json](examples/historical-session-rules.json)이며 이전 달력 보고서의 바이트 해시를 입력에 고정합니다. 기존 V1 달력·ReferencePack·V7 종목군을 수정하지 않는 별도 보강 보고서입니다.

수집은 공개 화면의 일반 양식을 사용합니다. 로그인·계좌 인증키는 사용하지 않으며 공개 양식 nonce와 쿠키를 로그·영수증에 출력하지 않습니다. 계획과 기존 성공 캐시를 먼저 검사하고 요청 예산이 부족하면 네트워크를 시작하지 않습니다. 요청 시작 간격은 최소 1초, 응답은 최대 3MiB, 리다이렉트는 자동 추적하지 않습니다. 실패한 예약은 자동 재요청하지 않으며 새 수집 폴더와 검토된 성공 seed로 이어갑니다.

실행 위치는 `AI/ai-server`입니다. 아래는 이번 로컬 증거를 감사하는 명령입니다. build는 새 출력에 한 번 실행하고 audit는 기존 출력 전체와 재계산 결과를 비교합니다.

```powershell
$ruleArgs = @(
  '--scope', '../../docs/examples/historical-session-rules.json',
  '--cache', 'research-artifacts/session-rules-20261105/sources-reviewed',
  '--parent', 'research-artifacts/calendar-sessions-20261105/report.json',
  '--output', 'research-artifacts/session-rules-20261105/report.json'
)
.\.venv\Scripts\python.exe -m app.replay.historical_session_rules audit @ruleArgs
.\.venv\Scripts\python.exe -m app.replay.historical_session_rules capture `
  --scope ../../docs/examples/historical-session-rules.json `
  --cache research-artifacts/session-rules-20261105/sources-reviewed --max-new-requests 0
```

새 빈 캐시에서 15개 원문을 수집하려면 공개 양식 초기화 1회와 본문 15회, 합계 최대 16회가 필요합니다. 이번에는 이미 확보한 실제 영수증 15개를 seed로 가져와 정식 캐시 생성·재감사 요청은 0회입니다. 원문·로컬 산출물은 기존 정책대로 Git에서 제외되며, 다른 환경에서는 같은 입력 범위의 원문을 확보해야 재실행할 수 있습니다.

시점 조회의 `rulePeriods`, `ordinaryCandidates`, `actualSessions`를 분리했습니다. 각 시장의 모든 관련 판본을 실제 확보한 시각 이후에만 그 시장의 기간별 규칙을 노출합니다. 목록 시행일·공포일을 과거 최초 공개 시각으로 소급하지 않습니다. 일반 후보는 시점 조회에서도 실제 세션으로 반환하지 않습니다.

## 수집·감사·고정 진행률
