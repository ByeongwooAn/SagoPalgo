# SagoPalgo 개발 진척도

기준일: 2026-09-30

이 문서는 [개인용 Windows 투자 어시스턴트 로드맵](personal-windows-investment-assistant.md)의 11단계를 동일한 비중으로 평가한 **기능 구현 추정치**입니다. 점수는 배포 준비도, 실계좌 거래 안전성, 수익성 또는 사용자 검증 완료율을 뜻하지 않습니다. 부분 완료 비율은 남은 기능의 규모를 고려한 수동 추정이며, 새 작업이 병합되면 다시 평가합니다.

| 단계 | 범위 | 점수 | 현재 상태와 남은 일 |
|---|---|---:|---|
| 1 | Flutter Windows 전환 | 100% | Windows Release 빌드와 데스크톱 UI 구현 완료 |
| 2 | 개인용 설정 | 100% | 로컬 프로필, PIN 보관, Provider 설정 완료 |
| 3 | KB 계좌 연동 | 100% | 계좌·잔고·보유 종목 조회 구현 완료 |

| 6 | AI 분석 | 90% | 보유·관심 종목 분석과 등록 보유 종목의 매입 원금 비중 신호 완료. KB 실계좌 평가 비중·실운영 데이터 검증 남음 |
| 7 | 알림 | 85% | 주기 분석과 알림 MVP, 건별 전달 실패 격리·이어받기 조회·앱 실행 중 중복 표시 방지 완료. 재시작 경계와 장기 운영 검증 남음 |

**계산:** `(1+1+1+1+1+0.90+0.85+1+1+0.69+0) / 11 ≈ 0.8582`이므로 전체 기능 구현 진척도는 **약 85.8%**입니다. 이전 추정치 85.4%에서 약 0.4%p 증가했습니다. 단계별 난도와 위험이 같지 않으므로 이 숫자만으로 완성도를 판단하지 않습니다. 특히 10단계의 남은 작업은 실제 자금이 움직이는 고위험 범위입니다.

## 이번 단계의 경계

- Windows 알림 대기 API에 사용자 범위의 배타적 `afterAlertId` 커서를 추가했습니다. 앱은 최대 5페이지씩 처리하고 다음 주기에 이어받으며, 끝에 도달하면 앞의 실패 건을 다시 확인합니다. 한 건의 표시·완료 기록 실패가 뒤의 알림을 막지 않습니다.
- 표시 성공 뒤 `/sent` 기록 실패는 앱 실행 중 메모리로 구분하여 표시를 반복하지 않고 기록만 재시도합니다. 앱이 그 사이 종료되면 중복 표시 가능성이 남고, 정확히 한 번 전달은 주장하지 않습니다. 실기기 장기 운영 검증은 아직 하지 않았습니다.
- 보유 종목 분석 요청에 등록된 활성 보유 종목의 **매입 원금 기준** 동일 종목 비중과 설정 자본금 대비 비중을 추가합니다. 동일 시장·종목코드의 보유 건을 합산하며, 자본금 미설정 또는 종목 기록 누락 시 임의 수치를 만들지 않습니다. 이는 KB 실계좌의 실시간 평가 비중이 아닙니다.
- Python 분석기는 권장 자본금 한도를 넘은 종목의 신규 매수 신호만 보류하고 손절·익절 판단을 우선합니다. 관심 종목에는 비중 신호를 적용하지 않습니다. 실주문 전송에는 영향을 주지 않습니다.
- 관심 종목 ID를 사용자 소유권으로 확인하고 실제 시세가 있을 때만 Python `WATCHLIST` 분석을 실행합니다. 가짜 매수가·손익률·손절·익절 기준은 만들지 않으며, AI 서버 장애 시에는 중립 `HOLD`로 저장합니다. 추천 이력에는 출처가 남고, 대시보드 대표 추천은 보유 종목 결과만 선택합니다. 모의·실주문 전송과는 무관합니다.
- KB `SSQM2341` 조회 API는 지정일의 체결·미체결 항목, 다음키, 주문번호별 최대 10페이지 대조 결과를 반환합니다. 전체 페이지 확인 여부는 `completeScan`으로 표시합니다.
- 수량으로 명확히 구분되는 `OPEN`·`PARTIAL`·`FILLED`만 표시하고, 거절 사유·취소 가능성·수량 불일치 또는 불완전한 페이지 조회는 `UNKNOWN`/`completeScan=false`로 남깁니다.
- 수동 승인 확인 시 승인 ID를 기본키로 한 `READY` 제출 가드를 같은 트랜잭션으로 저장합니다. 기존 승인 건은 `LEGACY_REVIEW`로 이관해 예약을 막습니다. 내부의 원자적 예약은 한 번만 성공하고, 예약 뒤 불명확하면 `UNCERTAIN`으로 남겨 재시도를 막습니다. `GET /api/v1/orders/approvals/{approvalId}/submission`으로 상태를 확인할 수 있습니다.
- 새 가드에는 승인 확인 후 90초의 예약 기한을 저장하고, DB 갱신 조건에서 만료를 차단합니다. 기한이 지난 `READY`는 조회 시 `EXPIRED`로 표시하며, 기존 기한 없는 `READY`는 `011` 마이그레이션에서 `LEGACY_REVIEW`로 바꿉니다.
- 새 승인은 KB 계좌·상품코드·인증값·엔드포인트의 HMAC 지문에 묶입니다. 승인 확인과 내부 예약에서 계좌 설정 변경을 차단하고, 상태 조회는 유효 기한 안의 변경을 `ACCOUNT_CHANGED`로 표시합니다. 기존 지문 없는 `READY`는 `012` 마이그레이션에서 `LEGACY_REVIEW`로 바꿉니다. 계좌번호 원문은 승인 DB에 저장하지 않습니다.
- `RESERVED`·`UNCERTAIN` 승인에 대해 알려진 주문번호로 KB 이력을 최대 10페이지 조회하고, 승인 당시 주문안과 조회 행을 함께 반환합니다. 조회 요약은 감사 기록으로 보존하지만 접수·체결을 자동 확정하거나 가드를 해제하지 않습니다.
- 주문번호를 모르면 날짜별로 최대 10페이지·200행을 조회해 승인 당시 주문안과 함께 보여줍니다. 페이지·행 수 한도나 반복 커서는 `completeScan=false`로 남기고 조회 요약만 저장합니다. 행의 유사성이나 빈 결과를 주문 성공·미접수 판단에 사용하지 않습니다.
- 별도 기본 OFF 실주문 스위치와 운영 IP/MAC 형식 점검을 추가하고, 민감값 없이 차단 이유를 API·Flutter 설정 화면에 표시합니다. 전송 어댑터 미연결 검사는 항상 실패하므로 모든 설정을 채워도 `canSubmit=false`입니다.
- 설정 화면에서 수동으로 KB `SSQM2341` 첫 페이지의 읽기 전용 조회 상태를 점검할 수 있습니다. 설정 누락 시 호출하지 않고, 결과는 `VERIFIED`·`CONFIGURATION_BLOCKED`·`UNVERIFIED`로만 표시합니다. 테스트는 모의 응답으로 통과했으며 실계좌의 조회 권한·응답은 아직 확인하지 않았습니다. 조회 성공도 주문 제출 권한을 뜻하지 않습니다.
- 주문 전송·자동 재시도·정정·취소 API는 추가하지 않았습니다. 가드 예약은 아직 전송 어댑터에 연결되지 않았습니다. 실계좌의 주문 이력 응답 검증은 별도 수동 확인이 필요합니다.

## 다음 우선순위

1. 새 수동 점검으로 실계좌의 읽기 전용 응답·권한을 확인하고 운영 IP/MAC 요구사항을 별도로 검증한 뒤, 가드 예약을 향후 전송 어댑터에 연결하며 사용자 재확인·실패 감사 로그를 완성합니다. 네트워크 오류 직후 자동 재전송은 금지합니다.
2. 모든 차단 조건과 계좌 권한을 확인한 뒤, 별도 승인 아래 소액 수동 주문을 검증합니다.
3. 체결·미체결·거절·정정·취소 상태를 지속 동기화합니다.
4. AI 분석 확장, 알림 장기 운영 검증, 배포 자동 업데이트를 마친 뒤 제한적 자동매매 여부를 재평가합니다.
