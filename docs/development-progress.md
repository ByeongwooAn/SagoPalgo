### A 묶음 구현과 검증 범위

- 설정 카드의 `사용 가능`을 `설정 완료`로 바꾸고 실제 API 호출 검증과 분리합니다. B2C API Key 연결 계좌 조회와 주문용 계좌번호 점검을 구분합니다.
- 보유 탭의 `KB 계좌에서 불러오기`에서 미리보기를 확인한 뒤 자본금·보유분을 각각 선택합니다. 자본금 기준은 결제기준 `ordr_psbl_csh`(주문가능 현금)이며 예수금·순자산을 자동 대입하지 않습니다. 미제공·음수·잘못된 값은 자본금 반영을 막습니다.
- 미리보기는 5분 동안 유효하며 사용자·연결 지문·KB 수량/평균 매수가·주문가능 현금·현재 앱 데이터를 묶어 검증합니다. 적용할 때 다시 조회해 변경되었으면 재확인을 요구합니다.
- 수동 등록 국내 종목과 겹치면 건너뛰고, 같은 연결의 KB 종목은 중복 추가 없이 수량·평균 매수가만 갱신합니다. 기존 손절·익절 기준은 보존합니다. 연결 설정 변경 시 기존 KB 보유분과 혼합하지 않습니다.
- 실제 매수일은 `NULL`로 보관합니다. 상장 시장이 미제공이면 사용자가 KOSPI/KOSDAQ/KONEX를 선택해야 합니다. 국내 6자리 종목코드 외 종목·0 이하 수량/평균 매수가·중복 응답 행은 보유분 반영을 막습니다.
- 응답에 없는 기존 KB 보유분을 매도로 추정해 삭제하지 않습니다. 유지 건수를 표시하고 매도 완료분은 사용자가 보유 목록에서 정리합니다. 가져오기는 전체 계좌 자동 동기화가 아닌 수동 스냅샷 갱신입니다.
- 포트폴리오 목록·합계는 동일한 현재가 조회값을 사용합니다. 같은 시장·종목은 한 번 조회하고 매수가 대체 시에는 등록 건별 매수가를 적용합니다. 양수 가격·종목코드·Provider 일치 여부를 확인하며 잘못된 시세는 다음 Provider로 넘어갑니다.
- 시세 출처·조회 시각·매수가 대체 여부, KB 스냅샷 반영 시각을 표시합니다. 모의매매 원장·실주문 전송은 변경하지 않습니다.
- 기존 DB에는 `015_kb_portfolio_import.sql` 적용이 필요합니다. 실제 계좌 앱과의 대조 및 Ubuntu 재배포 후 검증은 별도 운영 확인 항목이며, 코드 구현만으로 완료 처리하거나 기존 87.0% 점수를 올리지 않습니다.
- 검증: 백엔드 180건·Flutter 96건 통과, Dart 정적 분석 이슈 없음, Windows Release 빌드 성공. 자동 검증은 모의 응답 기반이며 실제 DB의 015 적용 검증은 포함하지 않습니다. 로컬 Docker Linux 엔진이 실행 중이지 않아 임시 MySQL에서의 마이그레이션 실행 검증은 수행하지 못했습니다.
