# U04 비용·세금 팩과 계좌 적용 대기

기준일: 2026-11-06. **공식 공개 요율·결제일 기준 세율 팩과 계산/차단 코드를 구현했습니다. 실제 OpenAPI 계좌 적용·징수 규칙 대조는 미완료**입니다. 후속으로 사용자가 제공한 거래내역의 정산 산식·조건부 MTS 소수점 수수료 가설을 각각 6/6건 대조했습니다. [실제 표본·실사용 기록 절차](cost-statement-reconciliation.md)를 따르며 OpenAPI 요율·우대기간·징수 규칙은 계속 미확인입니다. 이 상태를 일반 공개 수수료로 대신 확정하지 않습니다.

## 확인한 공식 근거

공식 원문 8개를 로컬 `AI/ai-server/research-artifacts/actual-costs-20261106`에 저장하고 수집 시각·SHA-256을 [출처 원장](examples/actual-cost-sources.json)에 연결했습니다. 비공개 계좌/API·주문은 조회하지 않았습니다.

- [KB 현재 수수료 안내](https://www.kbsec.com/go.able?linkcd=m06030007): 거래소·계좌·종목·매수/매도·자금 유형·매체를 구분한 합산 안내와 HTS/ARS/MTS 공개표를 확인했습니다. 이는 사용자의 OpenAPI 매체 매핑·우대 요율·징수 기간·최소 수수료를 확인한 것이 아닙니다.
- [KB OpenAPI 공식 소개](https://blog.kbsec.com/about/kb%EC%A6%9D%EA%B6%8C-open-api-%EC%82%AC%EC%9A%A9%EB%B2%95/): API 이용 조건과 거래 수수료는 별도 확인 대상입니다. 공개 HTS/MTS 숫자를 이 계좌의 API 수수료로 선택하지 않았습니다.
- [KB 2025년 거래세 안내](https://www.kbsec.com/go.able?idt=20241223&linkcd=s060901010000&seq=10007894): 2025-01-02 시행과 **2024-12-27 체결분부터**의 적용을 따로 명시합니다. 체결일의 연도만으로 세율을 선택할 수 없다는 실제 경계 사례입니다.
- [국회예산정책처 2025년 국세수입 전망](https://korea.nabo.go.kr/board/file/down.do?fid=33318259)의 2023/2024 세율과 [2026 대한민국 조세](https://korea.nabo.go.kr/board/file/down.do?fid=33319156)의 2026 세율·농특세를 대조했습니다. 기준은 해당 일반 과세 주권의 결제·양도일입니다.
- 협회에 게시된 [2009년 징수 변경 공지](https://m.kofia.or.kr/brd/m_31/view.do?seq=3302)는 매도 체결별 절사를 안내합니다. 과거 공지를 현재 KB OpenAPI의 전체 세목·체결 집계 계약으로 자동 승격하지 않습니다.

현재 KB 페이지의 원 미만 처리 문구는 파생·비상장 등 상품별로 구분돼 있습니다. 해당 문구를 상장 보통주에 복사하지 않았습니다. 국세 일반 끝수 처리도 체결 징수의 모든 세목에 일괄 적용하지 않습니다. 현재 계좌의 거래세·농특세 별도 징수/합산·반올림 적용은 미확인입니다.

### 소수점 상품은 제외

현재 데스크톱 안내·기존 모바일 안내·2025년 소수점 안내 PDF의 매도 추가 비용이 서로 다른 시점/맥락의 숫자를 제시합니다. [2025년 소수점 문서](https://fdata.kbsec.com/agree/notice50.pdf)는 매체별 수수료와 신탁 해지 비용, 회차별 실행을 설명합니다. 시점과 상품이 다른 비용을 온주 거래세나 현재 소수점 계약으로 합치지 않습니다. 소수점·ETF/ETN·NXT·해외·신용·특별 면세는 이번 계산 입력에서 거절하며 이후 상품별 계약으로 확장합니다.

## 팩과 계산 방식

[세율 팩](examples/actual-cost-tax-rules.json)은 KRX KOSPI/KOSDAQ 일반 과세 보통주의 8개 규칙을 기록합니다. 2026년은 확인일을 포함한 11-06까지만 다룹니다. 미래 기간은 자동 연장하지 않습니다.

| 결제·양도일 연도 | KOSPI 거래세 | KOSPI 농특세 | KOSDAQ 거래세 | KOSDAQ 농특세 |
|---|---:|---:|---:|---:|
| 2023 | 0.05% | 0.15% | 0.20% | 0% |
| 2024 | 0.03% | 0.15% | 0.18% | 0% |
| 2025 | 0% | 0.15% | 0.15% | 0% |
| 2026 | 0.05% | 0.15% | 0.20% | 0% |

입력에 확인된 `settlementDate`와 `settlementConfirmed`가 필요합니다. 코드가 T+2나 연말 휴장일을 추정해 넣지 않습니다. 날짜·세율 적용 범위·자료 가용 시각을 검사하며, 매수의 매도세는 0으로 구분합니다. 양도소득세·배당세·계좌 전체 세금 정산 도구는 아닙니다.

[KB 공개 수수료 카탈로그](examples/kb-public-fee-catalog.json)는 공개 채널의 구간·정률·정액을 보존하며 `accountApplicable=false`, `openApiMapping=UNCONFIRMED`입니다. 유효 시작일도 임의로 생성하지 않습니다. 따라서 실제 `FeeProfile`의 기본값으로 로드할 수 없습니다.

`app.replay.cost_rules`는 기존 IOC 호가 모형과 별도의 **실체결 입력 형식을 받는 사후 비용 원장**입니다. 공개 호가 한 레벨을 실제 체결 1건으로 바꾸지 않습니다. 입력 체결은 호출자가 제공한 자료이며, brokerReconciled=false로 표시합니다.

- 체결 ID 중복·같은 주문의 종목/시장/방향 충돌을 거절합니다. 일자가 다르면 재사용되는 주문 번호를 구분합니다.
- 모든 금액은 Decimal로 계산합니다. 요율 입력은 bps이며 **1bps=0.01%**, 0.015%는 1.5bps입니다. 세목별 반올림 전 금액을 분리해 보존합니다.
- 수수료 프로필은 계좌 별칭·API 채널·상품·현금·시장·적용 기간·근거 가용 시각을 검증합니다. 실제 계좌번호 대신 로컬 별칭을 사용합니다.
- 정률/정액 구간·최소 수수료·집계 단위(PER_FILL/PER_ORDER/DAILY_SYMBOL_SIDE)·1원/10원 절사/올림/반올림을 선언할 수 있습니다. 이는 확인한 계약 또는 **명시적 합성 시나리오**이며 코드가 KB 계좌 적용을 인증하지 않습니다.
- 일별 합산 시 계좌·종목·방향·날짜·시장/거래소·매체·현금을 구분합니다. 공개 합산 안내만으로 일별 집계를 기본 적용하지 않습니다.
- 세목별 체결 단위 반올림은 `--tax-rounding-scenario`를 명시한 연구 시나리오에서만 계산합니다. 원래 KB의 체결 집계 단위와 세목 처리 확인은 남습니다.
- 수수료 프로필 없음·세금 징수 규칙 없음·결제일 미확인·미래 근거/체결·지원 기간 밖은 `BLOCKED`입니다. 모르는 비용은 **null**, 최종 합계도 null이며 무료 거래나 다른 요율 fallback으로 처리하지 않습니다.

입력 팩·프로필·체결 목록의 해시를 보고서에 연결하고 결과 파일은 덮어쓰지 않습니다. 실제 입력 자료는 사용자 원본 파일에 보존되며 CLI는 이를 수정하지 않습니다. `ACCOUNT_DOCUMENT`는 근거 파일에 대한 사용자 선언이고 서버 검증·전자서명 인증 상태가 아닙니다.

## 실행과 기존 코드 호환

AI 서버 폴더에서 명시적으로 실행합니다.

```powershell
.\.venv\Scripts\python.exe -m app.replay.cost_rules --pack ../../docs/examples/actual-cost-tax-rules.json --fills private-fills.json --as-of 2026-11-07T00:00:00Z --output research-artifacts/cost-report.json
```

위 예시는 근거 수집 이후 시점의 사후 연구 조회이며 과거에 이 자료를 알고 있었다고 처리하지 않습니다. 프로필이 없으므로 차단 보고서를 남기고 종료 코드 1을 반환합니다. 전체 계산 시나리오는 0, 입력/파일 오류는 원문을 숨긴 고정 오류와 2입니다.

확인한 프로필을 별도 파일로 지정하려면 `--profile`, 합성 세금 반올림 조건은 `--tax-rounding-scenario`를 사용합니다. 실제 계좌의 프로필이나 임의의 기본 반올림 파일은 저장소에 만들지 않았습니다. [프로필](examples/fee-profile.schema.json)·[체결](examples/cost-fill.schema.json)·[반올림](examples/cost-rounding.schema.json)·[팩](examples/cost-rules.schema.json) 스키마를 관리합니다.

기존 `quote_execution.py`의 feeBps/sellTaxBps와 올림 계산은 **기존 연구 가정으로 유지**합니다. 이 모형의 잔량 레벨을 실제 체결로 간주하거나 미확인 계좌 프로필로 교체하지 않습니다. 새 계산기가 자동 주문·잔고·예약금에 연결되지는 않습니다. API·DB·운영 배포·EXE 변경은 없습니다.

## 검증 범위

기반 구현의 38개 테스트는 연도/시장 세율·연말 체결과 다음 해 결제·매수/매도·세목별 계산·요율/정액/최소 비용·집계 단위·경계 반올림·큰 정수·다른 계좌/종목/방향 분리·미래/누락/범위 차단·중복/변조 입력 구조·파일 덮어쓰기 방지를 다룹니다. **테스트의 체결과 수수료 프로필은 합성 자료**이며 실제 OpenAPI 비용 계약 전체 대조는 0건입니다. 이후 별도 관찰 도구에서 실제 거래내역 6건의 정산 산식·조건부 비용 가설을 대조했습니다. 이 관찰을 온주/API `Fill` 또는 확정 프로필로 바꾸지 않습니다.

[검증 요약](examples/actual-cost-validation.json)은 공식 원문 해시 확인과 미확인 상태의 합계 null을 구분합니다. 합성 100만원 매도 예시는 수수료 1.5bps와 1원 절사를 **가정한 경우에만** 수수료 150원·2025년 KOSPI 농특세 1,500원·합계 1,650원입니다. 실제 사용자 계좌 청구액이 아닙니다. 기반 구현 당시 전체 AI 회귀는 **1,271건 통과·실패/오류/제외 0건**, 기존 의존성 경고 1건이었습니다. 이후 관찰 도구를 포함한 [최신 검증](cost-statement-reconciliation.md)은 전체 실행과 fixture 보완 실행에서 고유 검사 1,298건 통과입니다.

## 현재 요청의 남은 작업과 완료 조건

**U04 잔여 단위: 실제 KB OpenAPI 비용 계약 확정·징수액 대조.** 아래 내용이 확인되면 프로필 적용과 회귀를 진행합니다. 추가 자료가 생길 때까지 실제 근거 대기로 관리하며, 다음 개발은 U05에서 비용 확정 없이 가능한 가격·수량 독립 대조부터 진행합니다.

1. 해당 계좌의 OpenAPI 주문매체 매핑·상품별 정률/정액·유관 비용 포함 여부·최소 비용·우대 시작/종료일.
2. 체결/주문/일별 수수료 합산 범위와 반올림 단위, 거래세/농특세 각각의 징수 단위·처리 순서.
3. 제공 가능한 실제 체결·정산 내역에서 계산값과 청구액을 대조하고 차이 사유 0건 또는 명시적 미확인으로 기록.

사용자는 현재 제공한 거래내역 외 추가 거래 자료가 없으며 향후 실사용 테스트에서 보완하기로 했습니다. [U04-A/B/C 실행 단위](cost-statement-reconciliation.md)에 계좌 계약·징수 대조·프로필 적용의 범위와 완료 조건을 정리했습니다. 이를 얻기 위해 실주문을 만들지 않았으며, 계좌번호·키를 채팅에 요청하지 않습니다. **U04는 계산 기반·공개 근거·실제 표본의 제한 대조 완료, 실제 OpenAPI 적용 확인 대기**로 유지합니다. U05의 비용 판정은 U04와 연결하고, U06 소켓 복구·U07 장기 운영·U08 과거 CB/단일가 표본은 별도 후속입니다. 고정 합계 27/48·56%, 5번 7/18·39%, 5-08 진행 중은 유지합니다.
