# U04 실제 거래내역 대조와 실사용 검증 대기

기준일: 2026-11-06. 사용자 제공 거래내역으로 **실제 정산 산식 6/6건과 조건부 수수료 가설 6/6건 일치**를 확인했습니다. 이는 현재 계좌의 OpenAPI 비용 계약 확인이나 세금·부분 체결 합산 규칙 확정이 아닙니다. 사용자는 현재 추가 거래 자료가 없으며 향후 프로그램 실사용 테스트에서 대조 자료를 보완하기로 했습니다. 확인을 위해 새 실주문을 만들지 않습니다.

## 실제로 확보한 범위

원본은 1개 시트의 2행 묶음 거래내역입니다. 전체 16개 거래 중 주식장내매수 4건·주식장내매도 2건을 추출했고 입출금·배당·예탁금 이용료 등 10건은 이번 매매 비용 대조에서 제외했습니다. 제외한 거래를 삭제하거나 성과 원장에 이미 반영한 것으로 처리하지 않습니다.

- 매수 정산금액 = 거래금액 + 보고된 수수료, 매도 정산금액 = 거래금액 - 보고된 수수료가 6건 모두 일치했습니다.
- 수량은 6건 모두 1주 미만입니다. 소수점 거래 정황은 있지만 원본의 상품·매체를 대신 확정하지 않고 `product/channel=UNCONFIRMED`로 보존합니다.
- 거래세 등 칸은 공란입니다. 농특세/부가세 칸의 명시적 0과 구분하며, 세금 면제나 실제 모든 비용이 0이라는 결론으로 바꾸지 않습니다.
- 거래일자는 체결일·결제일 중 어느 날짜인지 확인되지 않았습니다. `dateBasis=UNCONFIRMED`로 두고 T+2를 생성하지 않습니다.
- 주문·개별 체결 식별자가 없어 부분 체결 합산과 최소 수수료는 확인할 수 없습니다.

원본 SHA-256과 시트/행 범위를 각 관찰에 연결했고, 원본은 사용자 제공 경로에 그대로 두고 수정하거나 복사하지 않았습니다. 추출 자료·개인별 금액·상세 보고서는 로컬 `AI/ai-server/research-artifacts/cost-observations-20261106/`에만 보관합니다. 이 경로는 이미 Git 제외 대상입니다. 저장소에는 개인별 거래 행·계좌번호·종목명·엑셀 원본을 추가하지 않습니다.

## 계산 가설과 계좌 계약의 구분

사용자가 M-able에서 확인한 비대면/은행연계 계좌의 **MTS 국내 요율은 0.12%**입니다. 다음의 명시적 조건부 가설이 이번 6개 표본의 수수료와 일치합니다.

1. 기본 수수료: 거래금액 × 12bps에서 10원 미만 절사.
2. 매도 추가 비용: 거래금액 × 20bps에서 1원 미만 절사한 값을 기본 수수료에 추가.

[KB 현재 수수료 안내](https://www.kbsec.com/go.able?linkcd=m06030007)는 국내 소수점 매도에 매체별 수수료 외 신탁수익증권 해지수수료 0.2%를 안내합니다. 공개 안내는 추가 비용의 맥락이며, 이번 표본의 각 비용 항목·효력일·절사 방식을 공식 확정하는 근거로 사용하지 않습니다. 가설을 거래세/농특세로 재분류하지 않습니다.

사용자 제공 [OpenAPI FAQ](https://openapi.kbsec.com/community/10000000-0000-0011-0000-000000000001/post/53b0d49c-9d56-4a04-baf7-c53050537206) 발췌는 계좌별 HTS 요율과의 동일성 및 비대면 무료 이벤트 제외를 안내합니다. 해당 발췌는 사용자 제공 근거로 기록하며, 이 거래내역의 MTS 0.12%를 OpenAPI 요율로 복사하거나 공개 HTS 숫자로 실제 계좌 계약을 자동 확정하지 않습니다.

향후 해외 확장을 위한 사용자 확인값은 미국 0.25%·미국 소수점 0.25%·일본 0.30%입니다. 이 역시 사용자 M-able 확인값이며 해외 API 매체·제세금·환전·최소 비용·적용 기간은 미확인입니다. 현재 국내 비용 계산기에 적용하지 않습니다.

## 오프라인 대조 도구

`app.replay.cost_reconciliation`은 정규화된 **거래내역 관찰**을 받습니다. `cost_rules.Fill`에 필요한 체결 시각·결제일·온주/API 조건을 만들어 넣지 않습니다. [입력 스키마](examples/cost-observations.schema.json)와 [합성 입력 예제](examples/cost-observations.synthetic.json)를 제공합니다. XLSX 자동 가져오기·운영 API 연결·실시간 자동 대조 기능은 이번 범위가 아닙니다.

```powershell
# AI/ai-server에서 실행. 합성 예시이며 실제 계좌 비용이 아님.
.\.venv\Scripts\python.exe -m app.replay.cost_reconciliation --observations ../../docs/examples/cost-observations.synthetic.json --as-of 2026-11-06T12:00:00Z --mts-fractional-hypothesis --output research-artifacts/cost-observations-example.json
```

실제 입력은 로컬 정규화 JSON을 지정하고 `--evidence-file`에 원본 경로를 주면 SHA-256을 재확인합니다. 원본 경로가 없으면 `evidenceFileHashVerified=false`이며 정규화 행 자체의 정확성을 자동 인증하지 않습니다. 이번 실제 대조에서는 원본 해시 재확인까지 수행했습니다. 입력 해시·기록 시각·조회 시각·행별 출처·공란·원 단위 차이를 보고서에 남깁니다. 수량의 엑셀 지수 표기는 Decimal 고정 소수 표기로 옮기며 저장된 숫자를 반올림하거나 수량×단가로 거래금액을 복원하지 않습니다.

- `MATCH`: 입력에 명시된 비용 항목과 정산 차액 일치.
- `MATCH_WITH_UNREPORTED_COMPONENTS`: 알려진 비용을 빼면 차이가 없지만 공란 항목이 남음. 이번 6건 모두 이 상태입니다.
- `UNEXPLAINED_DIFFERENCE`: 정산 차액과 알려진 비용이 일치하지 않음. 누락 비용을 역산해 실제 세금/수수료로 채우지 않습니다.
- 가설은 플래그를 지정한 경우에만 계산하며, 매체가 미확인/MTS이고 상품이 미확인/소수점이며 수량이 1주 미만인 관찰에서만 조건부 비교합니다. HTS·OpenAPI·온주·수량 누락에는 적용하지 않습니다.

출력은 항상 `OBSERVATIONS_ONLY`입니다. 실제/합성 출처를 구분하고 `brokerReconciled`, 계좌 요율·세금·합산·최소 비용·반올림 확정, 전략/거래 사용 가능 여부는 모두 false입니다. `confirmedTotalCostWon=null`, OpenAPI 전체 비용 대조 0건을 유지합니다. 기존 `cost_rules`의 미확인 비용 차단도 유지합니다.

종료 코드는 보고서 작성 성공 및 비교 차이 없음 0, 정산 또는 가설 차이 발견 1, 입력/해시/파일 오류 2입니다. 0은 비용 계약 확정이나 거래 승인 코드가 아닙니다. 출력 파일은 배타적으로 생성하고 기존 보고서·입력을 덮어쓰지 않습니다. 오류 메시지에는 개인 입력 값을 출력하지 않습니다.

## 실사용 중 추가할 기록과 완료 조건

실제 자료가 생길 때마다 한 계좌·한 원본 단위로 별도 관찰 파일과 보고서를 만듭니다. 매체·상품·날짜 의미·주문/체결 ID를 모르면 null/UNCONFIRMED로 남깁니다. 식별자는 계좌번호 대신 로컬 별칭을 사용합니다. 근거가 없는 정상화 값을 입력하지 않습니다.

| 작업 단위 | 실사용에서 확보할 내용 | 완료 조건 |
|---|---|---|
| U04-A 계좌 API 비용 계약 | HTS/API 적용 요율·정률/정액·상품·우대기간·최소 비용·유관 비용 포함 여부 | 계좌 적용 근거와 유효기간을 프로필에 연결. MTS 표본으로 대체하지 않음 |
| U04-B 주문·체결별 징수 대조 | 원본 해시·날짜 의미·종목 별칭·방향·매체·주문/체결 참조·매매금액·수수료·거래세·농특세·기타 비용·정산금액 | 정상 주문과 부분 체결의 합산 단위/끝수 및 차이를 근거와 재현. 미확인/차이는 명시적으로 보존 |
| U04-C 계산 프로필 확정·회귀 | A/B의 확인된 범위를 기존 `cost_rules`에 적용하고 계산값/청구액 비교 | 지원 범위에서 차이 사유 해결·회귀 통과. 상품·매체·기간 밖은 계속 차단 |

현재 새 거래가 없어 A/B는 **실사용 근거 대기**입니다. 프로그램 테스트와 자료 축적을 통해 확인하며, 이 대기를 구현 실패나 추가 실주문 요청으로 바꾸지 않습니다. 모의 거래의 가상 비용은 실제 징수 근거를 대신하지 못합니다. 실제 주문 활성화는 T03의 별도 승인·제한 절차를 따릅니다.

**다음 개발 단위는 U05 체결 모형 독립 대조**입니다. 확보된 공개 체결·호가와 추정 가격/수량의 비교부터 진행하고 실제 계좌 체결·미확인 비용 항목은 판정 불가로 남길 수 있습니다. U04 실제 계약을 기다리는 동안 가능한 U05 범위를 진행하며 자동매매·수익성 검증 완료로 확대하지 않습니다. U06 소켓 복구·U07 장기 관찰·U08 과거 CB/단일가는 [남은 작업 단위](remaining-development-units.md)를 따릅니다.

## 검증 기록

실제 관찰 6건의 정산 산식 일치 6건·수수료 가설 일치 6건·설명되지 않는 정산 차이 0건, 공란 비용이 남는 관찰 6건입니다. OpenAPI/온주 계약 적용 대조는 0건입니다. 검증 요약은 [기존 U04 검증 원장](examples/actual-cost-validation.json)의 `statementReconciliation`에서 별도로 집계합니다.

신규 27개 테스트는 개인 원본을 쓰지 않는 합성 자료로 공란/0 구분·매수/매도·별도 세금/기타 비용·가설 불일치·HTS/API/온주 차단·날짜 경계·중복·정밀도·원본 해시·입력 보존·출력 덮어쓰기 방지·개인정보 비노출을 검사합니다. 관련 비용 테스트 65건 통과, 전체 AI 회귀는 1,297건 통과·환경 fixture 미지정에 따른 제외 1건·기존 의존성 경고 1건입니다. 이후 기존 Java/MySQL export fixture를 지정해 제외된 교차 검증 1건도 통과했습니다. 두 실행의 고유 검사 **1,298건 통과·실패/오류 0건·최종 미실행 0건**이며 최초 전체 실행의 제외 기록은 보존합니다. 입력 스키마 일치·합성 CLI·문서 링크·Git 제외도 확인했습니다. 고정 27/48·56%, 5번 7/18·39%, 5-08 진행 중은 유지합니다.
