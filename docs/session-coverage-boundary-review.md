# 5-08 추가 공지 양식·발표 경계·정정과 일반 세션 판단

[H03 날짜별 감사](historical-session-final-audit.md)에서 거래소 보도자료와 KIND를 교차 대조했습니다. 일반 후보를 날짜별 근거 범위로 구분하고 36개 CB 공지의 분 단위 발표 경계와 개별 종목 정정 2건을 확인했습니다.

장중 모델 후속: [거래중단·단일가와 재현 엔진 연결](intraday-session-replay.md)에서 목표 기간 안 CB 17쌍과 프로그램 호가 정지 100개를 제한 구간 134개로 변환했습니다. 부분 근거·과거 가용 시점 미확인과 일반 후보 보류는 유지하며, 아래 수집/판단 보고서는 그대로 보존합니다.

기준일: 2026-11-06. [직전 공지 목록 검토](session-exception-notice-inventory.md)에 이어 사용자가 요청한 네 작업을 수행했습니다. 목표 효력일 범위는 **2023-11-01~2026-11-02 KOSPI·KOSDAQ 보통주**이며, 추가 발표 검색 창은 **2022-01-01~2026-11-06**입니다. 이전 계획·원문·명세·보고서를 수정하지 않고 별도 증거와 판단을 생성합니다.

## CB 중단·재개의 정확한 의미

CB 발동과 해제 **18쌍**을 원문의 시장·날짜·초 단위 시각으로 연결했습니다. 목표 범위 안은 **17개 시장/날짜(KOSPI 11, KOSDAQ 6)**이며, 2026-11-06 KOSPI 1쌍은 범위 밖으로 보존합니다. 모두 두 원문 사이 20분을 확인하고, 해제 후 10분 호가접수/단일가 구간을 접속매매와 구분합니다.

예를 들어 2024-08-05 KOSPI는 [발동 원문](https://kind.krx.co.kr/external/2024/08/05/000338/20240805000684/99443.htm)의 14:14:30 중단과 [해제 원문](https://kind.krx.co.kr/external/2024/08/05/000369/20240805000754/99407.htm)의 14:34:30 호가접수 재개를 연결합니다. 원문에 명시된 10분 단일가를 적용한 접속매매 재개 기준은 14:44:30입니다. 날짜·시각은 한국 시각이며 마지막 값은 원문 두 개와 명시된 10분 규칙에서 산출합니다. 실제 틱 체결로 검증했다는 뜻은 아닙니다.

`quoteAcceptanceResumesAt`과 `continuousTradingResumesAt`을 분리하며 20분이 맞지 않으면 실패합니다. 2/3단계 발동 조건을 설명한 문구를 실제 2/3단계 발동으로 세지 않습니다. **사이드카 104건은 프로그램 호가의 효력 정지**이므로 전체 시장의 거래중단 구간으로 만들지 않습니다. 모든 장중 장애/중단이 확보됐다는 플래그는 계속 false입니다.

## 발표 경계와 정정

2022년 연말 공지가 2023년 연초 개장일을 안내하는 사례를 확인했습니다. 발표 창 안의 공지라도 적용일이 목표 시작일 전이면 실제 세션에 넣지 않습니다. 2022년의 의무보유·공매도·자기주식 정책처럼 적용 기간이 이후로 이어지는 안내도 남겼으며, 유한한 검색 창만으로 앞선 모든 조치의 효력이 소멸했다고 판단하지 않습니다.

[주성코퍼레이션 정정 원문](https://kind.krx.co.kr/external/2025/03/25/001486/20250325004237/99409.htm)은 실제 발행주식수를 반영해 평가가격 **2,340→2,370원**, 최고호가 **4,680→4,740원**, 최저호가 **1,170→1,185원**과 관련공시 설명을 바꿨습니다. 적용일 **2025-03-26**은 유지됩니다. 원본/정정 문서 2개와 두 접수번호의 연결, 전체 본문 차이·각 해시를 보존합니다. 현재 정정 가격을 과거 원본 가격으로 덮어쓰지 않습니다.

이 검토의 `knownAt`은 실제 검토 시각이며 `sourceKnownAt`은 수집 시각입니다. 발표일 문자열이나 현재 뷰어 순서를 과거 최초 가용 시각으로 소급하지 않습니다. 기존 동양철관 제목 정정 기록도 이전 보고서에 그대로 보존합니다.

## 일반 후보 1,448개의 판단

각 후보의 날짜에 개장일 근거와 정확히 하나의 검증된 규정 구간이 연결돼야 판단을 생성합니다. 중복 날짜·휴장일·기존 특수 세션과 중복·규정 구간 누락은 오류입니다. 현재 모든 후보에는 다음 세 보류 사유가 있습니다.

- `NOTICE_SCOPE_NOT_EXHAUSTIVE`: 선택한 양식/분류/표현 밖을 포함한 전체 변경 목록 미확정
- `PUBLICATION_PREHISTORY_UNBOUNDED`: 발표 창 이전부터 효력이 이어지는 모든 조치의 종료/적용 범위 미확정
- `CORRECTION_PUBLICATION_HISTORY_UNCONFIRMED`: 전체 정정·철회 및 과거 최초 가용 시점 미확정

확인한 장중 중단 17개 시장/날짜에는 `MARKET_WIDE_INTRADAY_HALT_REQUIRES_INTERVAL_MODEL`을 추가합니다. 기존 `ReferencePack.sessions`는 개장/종료 한 구간을 표현하므로 새 중단 증거를 삭제하거나 하루 전체 휴장으로 바꾸지 않습니다. 중단/단일가/접속매매 구간은 별도 `interruptionPairing`에 기록합니다.

명목 09:00~15:30의 규정 근거와 실제 중단 없는 하루의 확정을 구분합니다. 결과는 모두 `DEFERRED`, `actualSessionConfirmed=false`, `includedInReferencePack=false`입니다. 기존 특수 세션·달력·종목군 자료는 그대로 유지하고 학습·전략 검증·거래 사용을 활성화하지 않습니다.

## 재현과 예산

`app.replay.session_coverage_review`에 `plan/extend/collect/build/audit/review/audit-review/decide/audit-decision/as-of`를 추가했습니다. 연구용 CLI이며 FastAPI·운영 DB·배포·EXE·주문 코드는 변경하지 않습니다.

원문·영수증·불변 보고서는 `AI/ai-server/research-artifacts/session-coverage-20261106/`에 보관합니다. [제목/경계 검토 명세](examples/session-boundary-review.json)와 [분류 검토 명세](examples/session-category-review.json)는 목록·선행 보고서·문서·본문 해시와 판단을 고정하고 Git에서 LF를 유지합니다. 후속 계획은 선행 계획·영수증 스냅샷·원문과 사용량을 계승하며, 같은 요청의 원문을 다른 작업에서도 재사용합니다. 같은 URL을 다시 조회해 바이트가 달라진 기록도 별도 관찰로 보존하며 정정으로 자동 해석하지 않습니다.

| 실제 수집 | 신규 요청 |
|---|---:|
| 제목·경계 검색 | 356 |
| 필터 미적용으로 거부한 탐색 | 1 |
| 분류 수집 선행 계획 | 256 |
| 캐시 통합 후속 계획에서 추가 | 321 |
| 이번 작업 합계 | **934** |

분류 후속 계획의 누적 상한 768회에는 선행 256회가 포함되며 실제 누적 사용은 577회입니다. 제목 검색의 원문 재사용은 이 상한을 새로 소비하지 않고, 전체 합계에는 최초 조회한 356회를 한 번 포함합니다. 초기 두 계획에 겹쳐 이미 호출한 관찰은 합계에서 빼지 않습니다. 수집 시작 간격은 최소 1초이고, 실패/미확정 예약은 자동 재시도하지 않습니다. 인증 없는 KIND 공개 HTTP만 사용했습니다. 이전 작업의 269회와는 다른 이번 작업의 합계입니다.

아래 명령은 `AI/ai-server`에서 실행합니다. 기존 원문 캐시와 선행 작업 경로가 필요하며 재검증은 통신하지 않습니다.

```powershell
$py = '.\.venv\Scripts\python.exe'
$root = 'research-artifacts/session-coverage-20261106'
$parent = 'research-artifacts/session-inventory-20261105/review-report.json'
$rules = 'research-artifacts/kosdaq-rule-effective-20261105/report-v2.json'

& $py -m app.replay.session_coverage_review audit --job "$root/job" --output "$root/inventory.json"
& $py -m app.replay.session_coverage_review audit --job "$root/category-complete-job" --output "$root/category-inventory.json"
& $py -m app.replay.session_coverage_review audit-decision --job "$root/job" --parent $parent --rules $rules --inventory "$root/inventory.json" --review '../../docs/examples/session-boundary-review.json' --other-job "$root/category-complete-job" --other-inventory "$root/category-inventory.json" --other-review '../../docs/examples/session-category-review.json' --output "$root/session-decisions.json"
```

`as-of`는 해당 작업의 `--job/--parent/--rules/--inventory/--review/--output`에 `--at/--market`을 더합니다. 원문·명세·보고서를 다시 감사한 뒤 검토 시각 이전에는 판단을 반환하지 않습니다. 새 수집이나 범위 변경은 새 경로·계획·명세·보고서를 사용하며 기존 보고서를 덮어쓰지 않습니다.
