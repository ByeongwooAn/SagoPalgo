# 실시간 AI 단기 자동매매 개발 로드맵

기준일: 2026-11-02 · 상태: 합의된 목표를 구체화한 개발 계획. 이 문서의 추가는 기능 구현·배포·실거래 검증 완료를 뜻하지 않습니다.

이 문서를 **향후 개발 순서와 완료 조건의 단일 기준**으로 사용합니다. [기존 설계·구현 이력](../architecture/personal-windows-investment-assistant.md)은 보존하고, [개발 진척도](development-progress.md)는 현재 범위의 증거를 관리합니다. 보류한 작업의 범위와 재개·완료 조건은 [보류 작업](deferred-work.md)에서 관리합니다. 현재 배포 방식은 [Docker 구조](../architecture/docker-architecture.md), 목표 서비스·데이터 흐름은 [목표 아키텍처](../architecture/target-system-architecture.md)를 따릅니다. 과거 `sagopalgo_development_roadmap.pdf`는 이전 계획 자료이며 최신 진행 기준이 아닙니다.

R0의 착수 문서: [API 지원·계약 매트릭스](../contracts/trading-api-contract-matrix.md) · [KB 계약 보류·재개 조건](../contracts/kb-contract-blockers.md) · [단기·중기·최종 목표와 초기 운용 초안](initial-trading-policy.md). 문서 기반 조사를 완료했으며 KB 답변·실환경 권한/한도·운용 수치 확정은 남아 있습니다.

## 1. 최종 목표와 범위

KB증권 실계좌의 잔고·보유·주문 상태를 기준으로 시장을 지속 관찰하고, 과거 데이터로 검증한 AI·전략이 종목·시점·금액을 판단하는 개인용 단기 자동매매 시스템을 만듭니다. Ubuntu 서버가 앱 종료 중에도 수집·판단·주문 관리를 담당하고, Flutter Windows 앱은 실시간 조회·운용 설정·중지·성과 확인을 담당합니다.

| 사용자 목표 | 구현 범위 | 담당 단계 |
|---|---|---|
| KB 계좌에서 보유 종목 가져오기 | 계좌·보유 자동 동기화와 앱 자체 관심목록 | R0, R1 |
| HTS 수준의 실시간 가격 표시 | 체결·호가 구독, 장중 캔들 생성, 평가금액과 화면 자동 갱신 | R2 |
| 뉴스·공시 자동 갱신 | 공급자 제공 속도·한도 안에서 증분 수집, 정정·중복 관리 | R3 |
| 가격·뉴스·공시·거래·투자자별 동향 분석 | 데이터 시점과 품질을 반영하는 실시간 특징 계산·예측 | R2, R3, R6 |
| 조건 충족 시 단기 매수·매도 | 진입·손절·익절·시간 청산·장 마감 정책과 주문 실행 | R6~R8 |
| 미등록 유망 종목 발굴 | 시장 전체 1차 탐색 → 후보 압축 → 정밀 분석 | R4 |
| 실잔고에 맞춘 온주 분산 거래 | 주문가능금액·미체결 예약·보유 비중 반영 | R1, R7 |
| AI가 거래 금액 판단 | 예측·위험·유동성에 따른 목표 비중을 서버 한도 내 주문안으로 변환 | R6, R7 |
| 일·주·월·연 수익 차트 | 체결·비용·입출금 원장, 자산 이력, 기간별 성과 | R1, R10 |
| 다년간 과거 데이터 활용 | 데이터 확보·재현·학습·미래 구간 검증·모델 버전 관리 | R5, R6 |

초기 구현 제안은 국내 현물·한 계좌·검증 가능한 한 거래소·제한된 후보군입니다. 실제 적용 시장, 거래 시간, 판단 주기, 목표 보유 시간, 당일 청산 여부와 한도 수치는 R0에서 확정합니다. 화면이 실시간으로 갱신되는 속도와 전략이 재판단하는 주기는 따로 설정합니다. 초저지연 매매나 수익률을 보장하는 계획이 아닙니다.

미국주식 확장 시 필요한 데이터·학습·USD 주문 검증 순서는 [미국주식 AI 학습·자동매매 로드맵](us-equity-ai-trading-roadmap.md)을 따릅니다.

## 2. 현재 기반과 개발 원칙

| 현재 기반 | 재사용 방향 | 아직 필요한 작업 |
|---|---|---|
| KB 계좌·잔고 조회, 미리보기 후 자본금·보유 가져오기 | 계좌 어댑터·계좌 지문·정규화 | 지속 동기화, 수동 거래 반영, 원장 대조 |
| KB/KIS/Toss REST 시세·일/주/월봉 | Provider 경계·공급자 진단 | 스트리밍·분봉·시각/거래소 일치 |
| Naver/OpenDART 저장·수동/주기 수집 | 저장소·중복 키·수집 상태 | 증분 수집·원문 사건 추출·지연 관리 |
| Python `WEIGHTED_SIGNAL_V1` | 비교용 규칙 모델·정규화 계약 | 과거 데이터·학습·예측·성능 검증 |
| 모의 원장·주문 시뮬레이터 | 주문 상태·복구·영속화 검증 | 현실적인 체결·거래 비용·전략 검증 |
| 사전검증·승인·제출 가드·수동 주문 | 공통 주문 코어·감사 기록 | 실제 완료 계약, 잔량·변경·전송 불명확 상태, 자동 대조 |
| 현재 평가손익·모의 성과 화면 | 포트폴리오 UI·기본 집계 | 실계좌 비용·현금흐름·일별 자산·기간 수익률 |

실계좌 관련 근거는 [기존 주문 로드맵](../architecture/personal-windows-investment-assistant.md#10단계-주문-기능), [주문 흐름 통합 검증](../orders/order-lifecycle-acceptance.md), [실제 첫 일부 정정·취소](../orders/manual-partial-order-changes.md)에 연결합니다. 시뮬레이터 검증을 실제 KB의 체결·정정·취소 성공 근거로 사용하지 않습니다.

운영 원칙:

- KB가 계좌·주문·체결의 외부 기준입니다. 서버는 관측된 계좌 상태와 내부 주문 예약을 대조합니다.
- 시세·뉴스·수급은 시장 시각, 공개 시각, 수신 시각과 출처를 보존합니다. 추정치·확정치를 구분합니다.
- AI는 매매 의도·목표 비중을 제안하고 서버의 잔고·노출·위험 검증을 통과한 주문만 실행합니다.
- 운영 기본값은 자동매매 OFF입니다. 사용자가 운용 범위·한도를 활성화하면 범위 안에서 자동 주문하며, 매 주문 수동 승인을 최종 운영 방식으로 강제하지 않습니다.
- 데이터 수집·일별 자산 기록은 초기에 시작합니다. 학습·수익 차트를 만드는 단계까지 저장을 미루지 않습니다.
- 문서 작성, 코드 구현, 자동 검증, 실환경 검증, 배포 완료를 구분합니다. 미확정 API와 신규 인프라를 이미 지원·배포된 것으로 표시하지 않습니다.

## 3. 전체 순서와 의존성

| 단계 | 우선순위 | 선행 조건 | 대표 산출물 |
|---|---|---|---|
| R0 계약·운용 기준 확정 | P0 | 없음 | API 지원표, 지연/품질 기준, 운용 정책 |
| R1 계좌 동기화·원장 기반 | P0 | R0 계좌 계약 | 계좌 상태·예약·현금흐름·자산 스냅샷 |
| R2 실시간 시세·수급 | P0 | R0 데이터 계약 | 체결/호가 수집·장중 차트·데이터 기록 |
| R3 뉴스·공시 사건 처리 | P1 | R0 수집 계약 | 증분 수집·종목 연결·사건 이벤트 |
| R4 시장 후보 탐색 | P1 | R2, R3의 기본 수집 | 후보 순위·편입/제외 이력 |
| R5 과거 데이터·재현 환경 | P0 | R0 확보 범위, R2/R3 공통 형식 | 시점 일치 데이터셋·비용 포함 재현 |
| R6 학습·실시간 전략 | P1 | R4 후보, R5 검증 환경 | 버전 모델·전략·판단 기록 |
| R7 자금 배분·위험 통제 | P0 | R1, R6 출력 계약 | 목표 비중·주문안·원자적 예약 |
| R8 자동 주문·제한 실운영 | P0 | R1~R7 검증, R10 기본 원장·성과, 기존 주문 제약 해소 | 자동 주문·체결 대조·중지·복구 |
| R10 기간별 성과·운영 화면 | P1 | R1부터 기록, R8 전 기본 성과, 온주 원장 대조 후 기간별 성과 | 일/주/월/연 수익·원장 대조·운영 지표 |

R1·R2·R3는 R0의 해당 계약이 확정된 범위에서 병행할 수 있습니다. R5의 데이터 확보는 초기부터 진행하고, 최종 재현 검증은 공통 형식이 안정된 뒤 수행합니다. R10은 **온주 원장·일별 기록 → 모의 성과 → 제한 실운영 성과 → 기본 기간별 차트** 순으로 진행합니다.

기간 추정은 R0에서 API 권한·데이터 확보량·실계좌 검증 가능 시점을 확인한 후 작성합니다. 미확정 외부 계약에 임의의 완료일을 붙이지 않습니다.

## 4. 단계별 개발 항목과 완료 조건

### R0. API 계약과 운용 기준 확정

진행 기록: 2026-11-02 [지원표](../contracts/trading-api-contract-matrix.md)와 [보류 목록](../contracts/kb-contract-blockers.md)을 작성하고 [초기 운용·측정 초안](initial-trading-policy.md)을 연결했습니다. R0 전체 완료나 실운영 정책 확정을 뜻하지 않습니다.

- **작업:** 국내 대상 시장 온주의 조회·주문·취소·체결·거래시간·최소금액·정밀도·호출/구독 한도를 표로 정리합니다. 수급 자료의 지원 범위, KIS 실시간 데이터 권한, 과거 자료의 기간·해상도·저장/활용 조건을 확인합니다.
- **운용 결정:** 초기 시장·후보 수 상한, 전략 보유 시간, 재판단/중복 신호 간격, 장 마감·휴장·거래정지 정책, 일손실·종목/업종 한도, 긴급 중지 이후 취소/청산 정책을 정합니다.
- **변경 영역:** `docs`에 계약 근거·샘플·확인일을 관리하고 지원 능력 모델을 설계합니다. 인증값·실계좌 원문은 문서에 넣지 않습니다.
- **산출물:** API 지원표, 데이터/체결 지연 측정 계획, 초기 전략 명세, 미확정 질문 목록.
- **완료 조건:** 각 필수 계약에 공식 근거 또는 마스킹된 실환경 대조 증거가 있으며, 미지원·미확정 기능이 차단 경로로 정의됩니다. 종목별/계좌별 권한과 실제 성공 여부를 구분합니다.

### R1. 계좌 자동 동기화와 원장 기반

실환경 점검 후속: [2026-11-03 읽기 관찰·사용자 대조](../accounts/account-observation-live-validation.md). 로컬 배포에서 저장/상세/이력과 보유·현금 표시 일치를 확인했습니다. 지정일 주문 구간은 FAILED/LOOKUP_FAILED로 전체 관찰은 PARTIAL이며 정상 빈 결과의 계약을 KB-07로 분리했습니다. 수집·주문 OFF를 유지하고 전체 운영 완료로 표시하지 않습니다.

제한 운영 후속: [자동 1주기 중단·재시작·OFF 재개](../accounts/account-collection-operations.md)를 실제 로컬 배포에서 확인했습니다. 현재 수집 OFF·IDLE, 수동/자동 각 1건이며 정상 연속 수집은 KB-07·호출 예산 확정 후 별도 검증합니다. GET 전용 상태/이력 변화 점검 도구와 격리/모의 검증 근거를 추가했습니다.

첫 구현: 2026-11-02 [읽기 전용 계좌 관찰 계약](../accounts/account-snapshot-contract.md). 새 GET·구간별 시각/범위/완전성·소수점 보존과 격리 HTTP 검증을 추가했습니다. 자동 동기화·영속 원장·실환경 대조·배포 완료를 뜻하지 않습니다.

후속 구현: [계좌 관찰 저장·이력 조회](../accounts/account-observation-history.md). 명시적 요청·계좌/사용자 격리·불변 결과·023 마이그레이션·MySQL 동시/롤백 검증을 추가했습니다. 관찰 저장이며 자동 동기화·거래 원장·운영 적용 완료가 아닙니다.

관찰 대조 기반: [저장된 두 관찰 비교](../accounts/account-observation-comparison.md). 동일 연결·동일 구간 범위의 필드 차이와 십진 변화량, 불완전/역전/식별 불가 구간의 차단 사유를 반환합니다. 외부 재조회·원장 반영·주문 종결 판정 없이 비교하며 앱/운영 연결은 후속입니다.

앱 연결 구현: [계좌 관찰 이력·상세·비교 화면](../accounts/account-observation-ui.md). 보유/설정 진입·명시적 저장·로컬 요청 ID 복구·GET 상태 확인·부분 비교 표시와 모의 HTTP/위젯 검증을 추가했습니다. 운영 서버/앱 배포·실계좌 대조·자동 수집·원장 완료를 뜻하지 않습니다.

주기 수집 기반: [기본 OFF 계좌 관찰 자동 수집](../accounts/account-observation-collection.md). 024 실행 상태·DB 원자적 소유권·서버 재생성 후 저장 결과 대조·부분 실패 중단·상태/명시적 재개 API를 추가했습니다. 후속으로 [Flutter 상태/재개 패널](../accounts/account-observation-ui.md#6-자동-수집-상태와-재개)을 연결했습니다. 로컬 Docker 023·024 적용·API 응답 확인은 [진척도](development-progress.md)에 기록합니다. 운영 활성화·실계좌/장기 복구 검증·원장 자동 반영은 후속입니다.

- **통제:** 거래당 위험, 종목/업종 노출, 일간 실현+평가 손실, 주문 횟수, 가격 이탈, 데이터 신선도를 서버가 강제합니다. 예약·해제·체결 반영은 계좌 단위로 원자적 처리하고 여러 워커/재시작에서도 중복 사용하지 않게 합니다.
- **변경 영역:** Spring 자금 배분·위험 서비스와 주문 코어, DB 현금/수량 예약·노출·운용 정책, Flutter 운용 자금/한도·허용 모드 설정.
- **산출물:** 모델/전략 근거·유효기한이 포함된 주문안, 승인/거절 사유, 예약/노출 이력.
- **완료 조건:** 동시 후보·부분 체결·외부 수동 거래·거절/취소·장애 후 대조에서 잔고 초과·과매도·중복 예약이 없습니다. AI가 제안한 금액이 한도를 넘으면 축소 또는 거절됩니다.

### R8. 자동 주문 생명주기와 제한 실운영

- **선행 제약:** 실제 KB의 정정/취소 완료·잔량·주문 계보·예약금 계약을 확보합니다. UNKNOWN·시작 이후 SENDING/DISPATCHING·부분 체결/변경의 종결과 복구 근거를 검증합니다. 기존 문의/실환경 검증 미완료를 새 문서로 완료 처리하지 않습니다.
- **작업:** 수동 승인 경로와 별도로 사용자가 활성화한 자동 운용 정책에서 공통 주문 코어를 호출합니다. 신호·주문안·제출의 멱등 키, 전송 전 영속화, 주기 체결 조회/지원되는 체결 통보, KB와의 대조를 연결합니다. 불명확한 전송을 재전송해서 해결하지 않습니다.
- **중지/복구:** 수집 중단·모델 장애·잔고 불일치·손실 한도에서 신규 진입을 중지합니다. 중지는 미체결 취소·포지션 청산과 별도 동작이며 정책에 따라 실행합니다. 재시작은 실제 계좌 대조 후 사용자가 정한 재개 조건을 충족해야 합니다.
- **변경 영역:** Spring 자동 운용 관리자·기존 주문 코어/대조·DB lease/이력, Flutter 운용 모드·긴급 중지·미확정 주문 화면, 운영 경보.
- **산출물:** 모의 자동 운용, 제한된 종목/자금의 실운영 절차, 장애·복구·모델/전략 rollback 기록.
- **완료 조건:** 수신→판단→배분→주문→체결→원장→성과 흐름을 검증합니다. 격리 통합·실시간 shadow/모의·별도 승인된 제한 실거래·장기 운영을 순서대로 통과해야 실운영 완료입니다. 문서 작업의 승인은 실주문 승인이 아닙니다.

### R10. 기간별 수익·포트폴리오와 운영 가시성

- **초기:** R1에서 체결·입출금·배당·비용·일별 자산을 저장합니다. R7/R8의 모의·제한 실운영 전에 기본 손익·노출·현금 대조 화면을 제공합니다.
- **기간별 성과** — 국내 온주의 일·주·월·연 손익, 자산 곡선, 실현/평가손익과 비용을 구현합니다. 거래일·시간대·기준 통화와 평가 불가 시 처리 기준을 고정합니다.
- **수익률** — 입출금 효과를 제거하는 시간가중수익률의 산정 기준과 자료 가용성을 표시합니다. 일별 수익률을 합산하지 않고 기간 복리로 연결합니다. 과거 이력이 없으면 기록 시작 전 연간 차트를 임의로 채우지 않습니다.
- **변경 영역:** Spring 성과 집계 API, DB 원장·일별 평가·집계, Flutter 기간 선택·포트폴리오/운영 차트. 주문 접수 응답만으로 실현손익을 만들지 않습니다.
- **산출물:** 일/주/월/연 차트, 기준 통화/순입금/비용 표시, 동기화·시세·모델·주문 진단과 감사 이력 연결.
- **완료 조건:** 입출금·배당·비용·부분 체결·재시작·과거 재집계 사례에서 원장 및 KB와 대조합니다. 자료 미확보 기간과 평가 실패를 구분하고 수익률 산정 근거를 화면에서 확인할 수 있습니다.

## 7. 공식 자료와 해석 범위

- [KB Open API 문서](https://openapi.kbsec.com/apidoc_b2c): 공개 목록의 국내 소수점 주문/취소/조회·투자자·순위 API를 확인했습니다. 계좌 권한·호출 성공·완료 응답 의미와 지연은 별도 검증 대상입니다.
- [KB 국내 소수점 거래 안내](https://fdata.kbsec.com/agree/notice50.pdf): 회차별 처리와 6자리 수량이 안내됩니다. 일반 서비스 안내를 개별 API의 전체 계약으로 대체하지 않고 R0/R9에서 적용 조건을 대조합니다.
- [KIS 공식 Open API 예제](https://github.com/koreainvestment/open-trading-api): 실시간 체결/호가 WebSocket 어댑터의 참고 자료입니다. 계좌/주문은 KB만 담당합니다.
- [OpenDART 개발 가이드](https://opendart.fss.or.kr/guide/main.do): 공시 검색·원문 제공 범위와 요청 제한에 맞춰 수집합니다. 주식 체결과 같은 속도의 공급을 보장하지 않습니다.
- [시계열 검증](https://scikit-learn.org/stable/modules/generated/sklearn.model_selection.TimeSeriesSplit.html): 과거 학습·이후 평가의 기본 근거입니다. 겹치는 예측 구간의 추가 누출 방지는 데이터/목표에 맞게 설계합니다.
