### 5-17 — 상품별 소수점 주문 확장

- **필요 근거** — 소수점 상품을 운용하려면 최소금액·수량 정밀도와 회차별 체결·배분·취소 조건을 상품별로 확인해야 합니다. 중간 반올림은 주문 수량과 원장 대조에 영향을 주고, 회차 처리와 배분 지연은 전략의 진입·청산 시점에 영향을 줍니다. 국내 API 후보는 `SSAM5762/5763/5764`, `SSQM5765`입니다. 해외는 별도 계약으로 확인합니다.
- **보류 사유** — 현재 우선 범위는 온주입니다. 온주 주문·위험 통제·모의 체결·원장·성과는 기존 정수 수량 계약으로 검증할 수 있습니다. 소수점 주문 경로와 실제 상품 계약 검증은 온주 공통 흐름을 확인한 뒤 소수점 상품을 운용 범위에 넣을 때 재개합니다. [로드맵의 단계별 의존성](realtime-trading-roadmap.md#3-전체-순서와-의존성)

- **상품별 구현 범위** — 온주 주문과 소수점 주문 어댑터·보유·예약·체결 배분을 분리합니다. DB, DTO, 원장과 Flutter에서 DECIMAL·문자열 전송·십진 계산을 사용해 상품별 정밀도를 보존합니다. 국내 안내의 6자리 수량과 최소금액·잔량·통화·수수료·권리·취소 마감·배분 지연·정산·온주 전환을 검증합니다. 회차 처리 상품은 해당 주기에 맞춰 예측·청산하며 실제 체결 속도와 손절 가능성을 독립적으로 검증합니다. 지원표·운용 화면과 소수점 성과를 연결합니다.

## 관리 기준

- 외부 기관이나 공급자에 이메일 문의가 필요한 실행 단위는 사유와 문의 범위를 기록하고 보류합니다. 사용자 요청으로 재개할 때 문의를 발송합니다. 다른 근거로 진행할 수 있는 상위 작업은 실행 목록에서 이어갑니다.
- 현재 목표의 완료·안전 검증에 필요한 작업은 실행 목록에서 관리합니다. 거래일, 계약 답변, 실제 계좌나 자료를 기다리는 필수 작업은 선행 조건과 함께 표시합니다.
- 현재 범위의 완료를 가로막지 않는 확장이나 표본의 추가 정밀 검증은 이 문서에 등록합니다. 등록할 때 상위 작업 ID, 작업이 필요한 범위와 근거, 당장 미뤄도 되는 이유, 이미 확인한 결과, 재개·완료 조건을 적습니다.
- 등록하거나 재개 조건·운영 영향이 달라질 때 우선순위를 검토합니다. 검증·운영에 미치는 영향, 선행 작업과 대체 경로를 기준으로 보류 작업 간 순위를 정하고, 1부터 번호를 매겨 오름차순으로 배치합니다. 항목이 추가되거나 실행 목록으로 이동하면 남은 번호와 표 순서를 함께 갱신합니다.
- [현재 개발 진척도](numbered-work-progress.md#현재-개발-진척도)는 현재 범위의 번호 항목만 계산합니다. 번호 항목 전체를 옮기면 현재 범위의 분모에서 빼고 근거를 기록합니다. 하위 단위만 옮기면 상위 항목은 한 번만 계산합니다. 5-17 이동으로 48→47개, D01 독립 항목 이동으로 47→46개가 됐습니다. 기존 4번 D01의 보유 포지션·전략 후보 구독 의무는 이미 있는 5-10에 연결해 한 번만 집계합니다.
- 재개 시 실행 목록에 항목과 선행 조건을 반영하고 이 문서에 이동 날짜를 남깁니다. 번호 항목이 현재 범위로 돌아오면 진척도의 분모를 함께 갱신합니다. 보류 상태에서 완료된 항목은 완료 근거와 날짜를 남겨 이 문서의 완료 건수에 반영합니다.
