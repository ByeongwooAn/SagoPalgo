# 개인용 Windows 투자 어시스턴트 설계

이 문서는 SagoPalgo를 공개 앱스토어 출시용 서비스가 아니라, 개인이 Windows PC에서 실행하는 투자 분석 보조 프로그램으로 전환하기 위한 기준 설계와 개발 로드맵을 정리합니다.

## 방향성

SagoPalgo는 Flutter Windows 기반의 `.exe` 프로그램으로 실행합니다. 사용자는 본인 PC에서 본인 증권사 API Key를 등록하고, 계좌 조회, 보유 종목 분석, 시장 데이터 조회, 뉴스/공시 기반 AI 분석, 알림 기능을 개인 용도로 사용합니다.

핵심 원칙은 다음과 같습니다.

- 실제 계좌 조회, 주문, 체결 같은 금융 업무는 KB증권 Open API만 사용합니다.
- KIS와 Toss Open API는 계좌나 주문 연동 없이 주식 정보와 시장 데이터 조회 용도로만 사용합니다.
- 앱은 로그인 화면 없이 바로 로컬 개인 프로필로 진입합니다.
- 기본 시세 Provider 하나를 우선 사용하고, 장애나 데이터 부족이 있을 때만 fallback Provider를 사용합니다.
- AI 분석기는 증권사별 응답 구조를 직접 알지 못하고, 정규화된 내부 데이터 모델만 사용합니다.
- 자동매매는 초기 구현 대상이 아니며, 모의매매와 승인형 주문을 거친 뒤 제한적으로 도입합니다.

## API 역할 분리

| 영역 | 메인 | 보조 | 비고 |
|---|---|---|---|
| 계좌 조회 | KB증권 | 없음 | 실제 계좌가 KB이므로 KB 고정 |
| 보유 주식 분석 | KB증권 | 없음 | 보유 단가, 수익률, 비중 기준 |
| 주문/매수/매도 | KB증권 | 없음 | 추후 구현 시에도 KB만 사용 |
| 국내 현재가 | KB 또는 Toss | KIS | 하나를 기본값으로 쓰고 나머지는 fallback |
| 해외 현재가 | KB/KIS/Toss 중 선택 | 나머지 | 지원 범위와 안정성 확인 후 결정 |
| 종목 정보 | Toss/KIS | KB | 종목명, 시장, 경고, 랭킹 등 |
| 뉴스 | Naver News API 등 | 기타 뉴스 API | 원문 저장보다 링크/요약 중심 |
| 공시 | OpenDART | 없음 | 국내 기업 분석에 중요 |
| AI 분석 | OpenAI API 또는 로컬 LLM | 없음 | 개인 설정으로 선택 가능 |

같은 종목의 현재가는 원칙적으로 하나의 시장 가격입니다. 따라서 세 증권사 API에서 같은 가격을 매번 모두 호출해 평균을 내는 방식은 기본 전략으로 사용하지 않습니다. 여러 Provider는 가격 자체를 합치기보다 장애 대응, 데이터 품질 검증, Provider별 부가 데이터 보강 용도로 사용합니다.

## 데이터 흐름

```text
1. KB API에서 내 계좌와 보유종목을 조회합니다.
2. Market Data Provider에서 현재가, 캔들, 거래량, 시장 지표를 조회합니다.
3. News/OpenDART Provider에서 뉴스와 공시를 수집합니다.
4. Provider별 응답을 내부 표준 모델로 정규화합니다.
5. AI Analysis Service가 종목별/계좌별 리포트를 생성합니다.
6. Alert Service가 가격, 뉴스, 공시, AI 신호 조건을 평가합니다.
7. Flutter Windows 위젯, 대시보드, Windows 알림으로 결과를 표시합니다.
8. 추후 주문 기능은 KB Order Safety Service를 반드시 통과합니다.
```

## AI 분석 기준

AI 분석은 직접적인 투자 권유보다 개인 판단을 돕는 참고 신호로 표현합니다.

권장 표현:

- 관심
- 관망
- 주의
- 리스크 증가
- 추가 확인 필요
- 목표 조건 접근

피해야 할 표현:

- 지금 매수
- 즉시 매도
- 수익 보장

## 자동매매 안전장치

자동매매는 초기 구현 대상이 아닙니다. 추후 구현하더라도 다음 단계를 순서대로 통과해야 합니다.

1. 모의매매
2. 주문 전 확인 팝업
3. 수동 승인 주문
4. 제한적 자동매매

필수 안전장치:

- 기본값 자동매매 OFF
- 실전투자보다 모의투자 우선
- 1일 최대 주문 횟수 제한
- 1회 최대 주문 금액 제한
- 종목별 최대 보유 비중 제한
- 손실 한도 도달 시 자동 중지
- 모든 판단, 조건, 주문 요청, 응답 로그 저장
- AI 단독 주문 금지 옵션

## 개발 로드맵

### 1단계: Flutter Windows 전환

- 상태: 완료
- Windows 빌드 활성화 상태 확인
- `.exe` 실행 확인
- 기본 창 제목과 앱 메타데이터를 SagoPalgo로 정리
- 기존 모바일 UI가 데스크톱 화면에서 깨지지 않도록 1차 점검
- Windows 빌드 환경에는 Visual Studio의 `Desktop development with C++`, `C++ CMake tools for Windows`, `Windows 10 SDK`가 필요합니다.

### 2단계: 개인용 설정 구조 정리

- 상태: 완료
- Google/Naver 로그인 화면 제거
- 개인용 로컬 사용자 세션으로 즉시 대시보드 진입
- 백엔드에서 로그인/JWT/OAuth 코드 제거
- 백엔드 개인용 모드에서 로컬 사용자 ID 주입
- `users` 테이블은 다중 회원이 아니라 로컬 소유자 호환 테이블로 유지
- Windows Credential Manager 기반 앱 잠금 PIN 등록·변경·삭제 구현 완료
- 기존 `SAGOPALGO_APP_LOCK_PIN`의 1회 자동 이전 구현 완료
- KB/KIS/Toss Provider 설정 분리
- 증권사 연동 상태 조회 API 추가
- Flutter Windows 설정 탭 추가
- 주문 권한 기본 OFF
- Windows 로컬 PIN은 Credential Manager, Ubuntu Provider 비밀값은 서버 `.env.prod`로 분리

### 3단계: KB 계좌 연동

- 상태: 완료
- KB Open API 인증 연동
- 계좌 목록 조회
- 보유 주식 조회
- 평가금액, 손익률, 비중 계산
- 계좌/잔고 상세 TR 경로와 필드명은 KB증권 Open API 포털 문서 기준으로 `.env`에서 설정

### 4단계: 시장 데이터 Provider 정리

- 상태: 완료
- KB 시세 Provider 구현
- KIS/Toss 읽기 전용 Provider 추가
- 현재가, 등락률, 캔들, 거래량 내부 모델 정규화
- Provider 장애 시 fallback 구조 추가
- KB `IVS11560`과 KIS `FHKST03010100` 기반 일·주·월봉 실데이터 조회 API 구현 완료
- Flutter 보유 종목 상세 일·주·월봉 차트와 실제 응답 Provider 표시 구현 완료

### 5단계: 뉴스/공시 수집

- Flutter 뉴스/공시 타임라인, 종목 선택, 필터, 수동 동기화, 원문 열기 구현 완료
