# U06-B KIS 장중 복구 실증 실행기

KIS 공개 시세 수집기의 실제 자동 재접속을 한 번 관찰하는 수동 실행기입니다. 기존 Java 수집기를 별도 JVM에서 사용하고, 실행기 소유의 루프백 TCP 중계기에서 첫 연결만 끊습니다. 저장은 중복 식별자를 확인하는 메모리 저장소로 처리합니다. 운영 DB 커밋 대조는 U07-C의 범위입니다.

## 장중 시작 조건

- KRX 휴장·임시 거래시간 변경을 확인한 당일 평일에만 실행합니다. 실행기가 받는 시간은 한국시간 09:05 이상 15:17 미만입니다. 이 구간은 검증 여유를 둔 실행기 제한입니다. [KRX 거래시간·휴장 규칙](https://global.krx.co.kr/contents/GLB/06/0602/0602010201/GLB0602010201T1.jsp)
- 실제 실행 시점에 KIS 키를 공유하는 다른 프로그램이나 수집기가 없고 1종목의 체결·호가 두 구독을 사용할 수 있는지 확인합니다. 같은 실행기도 한 번만 시작합니다. 이전 표본 종목은 삼성전자 `005930`입니다.
- 개인 로컬 분석 범위를 확인합니다. 실행기는 프로세스 환경의 KIS 키·시크릿을 우선 사용하고, 필요하면 프로젝트 루트 `.env`의 해당 값을 읽습니다. 운영 스트림 활성화 표시가 발견되면 중단합니다. 자격값은 명령 인자나 결과 파일에 넣지 않습니다.

Java 17 환경의 `Back/spring-server`에서 실행합니다. 아래 날짜는 예시이며 실제 KRX 거래일과 실행 날짜를 확인하고 바꿉니다. 확인 플래그는 실행 시점의 조건을 점검한 후에 지정합니다.

```powershell
.\gradlew.bat runKisIntradayRecoveryProbe --args="--market-date 2026-11-09 --stock-code 005930 --confirmed-regular-session true --confirmed-two-exclusive-subscriptions true --confirmed-personal-use true"
```

## 연결과 종료 기준

1. 공식 운영 승인 주소로 POST 한 번을 허용합니다. 실제 수집기의 승인키 재사용으로 최초 연결과 재접속을 수행합니다. 각 연결에서 `H0STCNT0`와 `H0STASP0` 두 구독을 요청합니다.
2. 첫 연결의 두 구독 응답과 새 체결·호가, 원문 표본을 최대 32초 기다립니다. 준비가 관찰된 경우에만 해당 TCP 중계 연결의 양 끝을 닫습니다. 다른 프로세스나 연결의 제어는 실행기에 포함되지 않습니다.
3. 같은 JVM의 수집기가 `RECONNECTING`을 거쳐 새 세대로 전환하는지 확인합니다. 두 번째 연결에서 두 구독 응답과 새 체결·호가를 최대 38초 기다립니다. 중계기는 세 번째 이후의 외부 소켓 시도를 차단합니다. 안정 시간 전 실패 예산이 초기화되거나 회복 후 중지 전에 다시 끊기면 판정은 미확정입니다.
4. 수집기를 중지한 후 6초간 추가 연결이 없는지 확인합니다. 준비 확인을 통과한 프로브 JVM에는 110초의 강제 종료 제한이 있습니다. 강제 종료 뒤에는 종료 표식 유무와 남은 기록의 검증 범위를 사용합니다.

## 결과 파일과 판정

출력 위치는 Git에서 제외되는 `Back/spring-server/build-codex-kis-recovery/<실행별 폴더>`입니다.

| 파일 | 내용 |
|---|---|
| `receipt.json` | 최초/복구 세대와 체결·호가 식별자, 승인·연결·중복 건수, 중지와 무결성 상태 |
| `public-frames.json` | 디코딩 및 구독 검증을 통과한 공개 시세 메시지 본문, UTF-8 SHA-256, 수신 시각, 세대, 이벤트 ID. 승인·구독 응답과 계좌 통보를 보관하지 않음 |
| `journal/session-*.jsonl` | 연결 상태·진단·시계 도메인·단조 경과 시각·건수. 기존 운영 상태 보고서에서 읽을 수 있음 |

공개 시세 메시지 본문은 최대 8 MiB, 관찰 이벤트는 최대 12,000개입니다. 상한에 걸리면 관찰을 중단합니다. 복구 결과가 `RECOVERY_OBSERVED`이고 중지·저널 검증까지 통과하면 종료 코드 0입니다. 수신 부족, 추가 단절, 상한 도달 등은 `INCONCLUSIVE`와 종료 코드 1입니다. 날짜·확인·실행 조건 오류의 종료 코드는 2입니다.

중복은 같은 이벤트 ID 기준입니다. 누적 거래량 경계는 단절 전 같은 날짜의 최고 관측 누적량과 복구 후 처음 관찰한 새 체결을 비교합니다. 초과 수량은 표본에서 관측하지 못한 수량의 단서입니다. 체결 건수, 거래소 원장 완전성, 공급자 측 구독 해제 완료 시점은 추가 근거가 있어야 확정할 수 있습니다.

## 진행 상태

2026-11-07 토요일에는 루프백 TCP와 합성 체결·호가로 준비 검증을 진행했습니다. 첫 연결을 실제 TCP로 끊은 뒤 같은 수집기가 두 구독에 다시 응답을 받고 새 시세를 처리했습니다. 합성 표본에서 원문 6건의 해시·이벤트 ID, 유일 이벤트 4건·중복 2건, 누적량 경계의 관측 초과 2주, 정상 END를 대조했습니다. 세 번째 이후 로컬 시도를 반복해도 시험 서버 연결은 2개였습니다.

주말 날짜를 지정해 실제 Gradle 명령을 실행했을 때 `KIS_RECOVERY_PROBE_OUTSIDE_KRX_WINDOW`와 프로브 종료 코드 2가 발생했고 실행 결과 폴더가 생성되지 않았습니다. Java 17 전체 백엔드 837건이 통과했습니다. 신규 실행기 9건을 포함하며 실패·오류·제외는 0건입니다. 시장 자료·계좌 관찰·주문의 전용 MySQL 회귀를 실행했습니다.

실제 장중에 `receipt.json`과 저널을 확보해 U06-B를 판정합니다. U07-C 격리 DB 장애·재시작 대조는 사용자 요청에 따라 장중 실증 이후에 시작합니다. [남은 실행 단위](remaining-development-units.md)
