# U07-C 격리 DB 재시작 대조와 U07-D 세션 관찰

## U07-C 격리 DB 장애·재시작 대조

표식이 있는 전용 MySQL과 루프백 WebSocket에서 수집기 자식 JVM을 종료한 뒤, 새 JVM으로 같은 합성 시세를 재생했습니다. 장애 전후의 원문·이벤트 ID·DB 커밋 행·저장 페이로드 해시·저널을 별도로 비교했습니다. 부모 테스트만 테스트 DB를 초기화합니다. 자식 JVM은 같은 DB의 행을 보존하면서 다시 수집합니다.

| 조건 | 첫 프로세스의 DB/저널 | 재시작 후 실제 커밋 |
|---|---|---|
| 분봉 UPDATE에서 MySQL이 쓰기 오류 반환 | 원본 체결 이벤트와 분봉 변경이 함께 롤백. DB 2행, 저널 삽입 반환 2·실패 1 | 롤백한 체결이 처음 저장됨. 새 삽입 3·중복 2 |
| DB 커밋 직후 저장 메서드가 반환하기 전에 프로세스 종료 | DB 3행, 저널 삽입 반환 2·진행 중 1 | 이미 커밋된 체결은 중복으로 처리. 새 삽입 2·중복 3 |

두 조건 모두 최종 DB **5행**의 이벤트 ID와 페이로드가 원본과 일치했습니다. 체결 3건의 분봉 거래량은 3주였고, 중복 재생으로 거래량이 늘지 않았습니다. 기존 저널 바이트는 보존됐고 새 프로세스의 별도 저널에서 END를 확인했습니다.

강제 종료된 저널에는 END가 없습니다. 특히 진행 중 1건의 결과는 저널만 읽으면 미확정입니다. 이 표본에서는 DB에서 동일한 이벤트 ID와 페이로드를 찾아 커밋을 확인했습니다. 표본 밖에서 관측하지 못한 이벤트나 종료 뒤 기록 수는 미확정으로 유지합니다. 분봉 쓰기 장애는 SQL 오류로 주입했으며 DB 서버 전체 재부팅은 이 시험에 포함되지 않습니다.

전용 시장자료 DB가 실행 중인 Java 17 환경의 `Back/spring-server`에서 테스트합니다. 테스트는 DB 이름과 격리 표식을 검사합니다. 결과는 Git 제외 경로 `build-codex-u07/restart/<시나리오>/comparison.json` 및 같은 실행의 저널에 남습니다.

```powershell
$env:SAGOPALGO_MARKET_RESEARCH_MYSQL_TEST='true'
.\gradlew.bat test --tests '*StreamRestartMysqlIntegrationTest'
```

## U07-D 관찰 계획과 보고서

연속 날짜 최대 31일의 거래일 계획을 작성합니다. 현재 계획 계약은 공개 KRX 1종목과 체결·호가 2구독입니다. 날짜마다 `OPEN`, `CLOSED`, `UNKNOWN`을 명시합니다. OPEN에는 해당일의 현지 개장·마감 시각이 필요하며, OPEN/CLOSED에는 보관한 일정 근거의 식별자를 넣습니다. 평일이라는 이유만으로 OPEN을 부여하지 않습니다. 예제의 일정과 출처는 합성입니다. [계획 JSON](../examples/stream-session-observation-plan.json)

전용 수집 범위의 저널 디렉터리를 지정합니다. 저널에는 종목과 구독 승인량이 없으므로 그 값은 계획에 적은 범위입니다. 날짜와 구간 분류는 Asia/Seoul로 환산한 로컬 관찰 시각을 사용합니다. 시각이 역전된 세션은 시간대 집계에서 제외하고, 해당 파일의 무결성·해시는 별도로 보고합니다. 손상되거나 잘린 저널은 검증된 접두부까지만 사용합니다.

```powershell
.\gradlew.bat reportStreamSessionObservation --args="--directory <저널폴더> --plan ../../docs/examples/stream-session-observation-plan.json --output <새결과파일.json>"
```

| 보고 내용 | 판정 범위 |
|---|---|
| 개장 전, 개장 직후, 일반장, 마감 직전, 마감 후 | 개장·마감 각 5분을 경계로 분리. 10분보다 짧은 세션은 경계 구간을 각각 절반으로 제한. 정확한 마감 시각은 마감 후로 집계 |
| 장중 15분 구간 | 검증된 저널 행의 유무. 구간에 행이 없어도 거래나 연결의 실제 부재는 판정할 수 없음 |
| 휴장일 | 연결 활동 관찰, 다른 기록은 있으나 연결 활동 미관찰, 기록 없음으로 구분 |
| 재시도·실패·자료 준비 | 날짜별 발생 횟수와 해당 세션 ID. 개별 복구 경과는 같은 ID로 U07-B 보고서에서 대조 |
| 일정 미확인 | 관찰 기록 수를 보존하고 개장·마감 구간 집계는 보류 |

기록이 모든 15분 구간에 있어도 공급자 시세의 연속성은 미확정입니다. 보고서는 기록이 있던 구간을 보여 줍니다. 새 파일에만 저장하고 원본 저널은 읽기 전용으로 처리합니다. [세션별 복구 지연 보고서](stream-operations-status-report.md)

실제 U07-D의 완료 조건은 계획 기간 동안 개장 전부터 마감 이후까지의 장중 자료, 휴장일의 별도 실행·미실행 근거, 재접속과 저장 기록입니다. 2026-11-16 [U06-B 실제 장중 복구](kis-intraday-recovery-probe.md#2026-11-16-실제-장중-실증)를 확인했습니다. 2026-11-22에는 1종목·2구독으로 거래일 4일·휴장일 2일 관찰을 완료하고 정상 종료, 저널과 DB의 날짜별 저장 집계, 휴장일 미실행을 대조했습니다. [실제 관찰 결과와 한계](kis-session-observation-20261117.md#2026-11-22-관찰-결과)

Java 17 전체 백엔드 846건이 통과했습니다. U07-C의 실제 자식 JVM·MySQL 대조 2건과 U07-D 보고서 7건을 포함하며 실패·오류·제외는 0건입니다. 실제 Gradle 명령으로 롤백/재시작 저널 2개와 4일 합성 계획을 비교했습니다. 개장일 검증 기록 19개와 미관측 구간, 기록 없는 휴장일 2개, 일정 미확인 1개를 구분했습니다. 입력 저널 파일의 SHA-256은 실행 전후 일치했습니다.
